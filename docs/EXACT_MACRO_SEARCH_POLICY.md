# 精确宏合成：搜索方式与切换依据

最新 111/325 案例的整改依据见 [合成逻辑审计](EXACT_MACRO_SYNTHESIS_AUDIT_2026_09_30.md)，本次实现与实测见 [第一阶段验收](baselines/2026-09-30-exact-macro-stage1.md)。网页实际使用贪心有序构造与真实回放；有界 Z3 是独立诊断路径。

网页第一阶段验收为全部主动施放的技能 ID、名称/变体、顺序、次数、引导跳数以及每次绝对时间误差。默认容差 62.5ms，必要时可放宽至 125ms，不累计漂移；内部状态快照独立诊断，不作为此模式的否决条件。验证至目标末次主动施放后 125ms，窗口内的等待与额外动作仍检查，不强加原来六秒停手。底层 API 默认仍保留旧的 `skills_and_state` 严格模式，网页合成器显式使用 `skills_and_time`。

所有候选交给原有 Rust 宏执行器；搜索首次确定失败立即停止，成功后独立完整回放才标记 `exact`。不限制宏行数、行内条件数或任务总时间，不加字数惩罚，不运行合并/压缩后处理。

## 什么时候用什么方法

| 情况 | 当前方法 | 目的与边界 |
| --- | --- | --- |
| 新场景、还没有候选 | 有序规则整体构造 `construct` | 建立第一份可回放宏；不是按目标序列直接写步骤。 |
| 首次分歧是目标动作尚未施放，且此前轨迹对齐 | 补充可执行目标动作的区分规则，再试时间阈值 | 只排除未被更早规则保护的可执行错误动作；不是强迫所有非目标条件为假。 |
| 技能正确但过早，尤其该规则此前未实际使用 | 合法时间门槛 `clock_gates` | 从实际 Buff 剩余时间寻找能在该动作容差窗口内翻转的条件；回放验证，不能只删除规则或改命令。 |
| 首次分歧是错误动作先释放 | 抢占规则拆分 `guard_trials` | 在实际抢占的规则上增加区分条件，检查优先级；之后完整回放。 |
| 某个目标前缀连续 24 次局部回放仍未严格改进 | 整宏有序规则重构 | 局部队列让位于全局搜索，不把既有前缀规则冻结。新最佳前缀出现后重新开放局部搜索。 |
| 等待区间错过目标动作 | 可撤销的 cast-now / 唤醒阈值分支 | 检查等待与扫描时刻；分支不成为永久的“必须立即施放”约束。 |
| 有限规则槽位/条件数下需要诊断 | 有界 Z3 路径 | `UNSAT` 只说明该有限编码无解；`UNKNOWN` 或超时不是无解。网页原型优先用无行数上限的构造路径。 |

局部队列最多保留 64 个分支；24 是**同一最佳前缀上的局部回放配额**，不是任务总轮数，也不限制宏的表达长度。新发现的反例可让先前表现相同的原子重新区分。局部和整体候选都只使用宏语法支持的条件，并由同一模拟器执行。

无引导及引导预释放的固定场景中，搜索动作目录只保留 `/cast`，避免等价 `/fcast` 重复探索；有引导时保留两种命令。这是搜索前的语义规范化，不是事后压缩。构造器交替尝试稳定条件优先与覆盖优先，仍可任意使用时间条件，也不预先按 last_skill 分组。行内仅去掉当前区分证据上冗余的条件，之后真实回放；不将样本等价当作调度等价。

候选到达路径分别保存，不能把互斥路径的要求合成全局硬约束。每次用一条路径的已到达前缀，加目标参考的未到达后缀作为构造指导；有限分支冲突释放该分支，必要时放宽参考后缀的等待指导或扩充实际失败点附近的一位小数阈值。每个新宏仍从零回放，没有检查点复用或前缀规则冻结。

## 之前卡住的原因与历史测量

暂停记录的 530 轮中，501 轮是局部阈值修改，只有 1 轮局部规则拆分、29 轮整宏构造。第 193 轮达到 84/324 后，至第 530 轮没有再次进行整宏构造：局部候选不断扩增队列，导致算法选择失衡。

改动后从该记录的 84 步候选**续算**的离线实验，在人为限定的 64 轮、约 35 秒内推进至 114/324。第 25 轮整宏构造推进到 96 步，第 51 轮整宏构造推进到 114 步。64 轮限制仅用于这次实验；线上任务没有这个轮数限制。这个实验还没有证明该起点能完成 324 步。

另一个已保存的 300 步候选续算实验，5 轮、约 20 秒达到 324/324，并通过独立完整回放；最大时间误差 106 ms，容差 125 ms。这是该起点的结果，不能外推为从头合成的耗时或保证。

## 判定与后续边界

每轮先找真实回放的首次分歧；只使用该点之前已对齐的状态学习。抢先施放、漏放、等待边界分开处理。局部方法连续无进展时切换整体重构；整体方法也可能长期无进展，所以界面继续显示已回放的最佳宏和首个分歧。当前有限原子目录与 AND 规则语言仍可能无法覆盖某些合法宏；样本约束互相冲突时只报告当前搜索空间或分支的障碍，不宣称所有宏无解。

本次没有加入跨任务宏复用，也没有把既有合格宏当成当前任务的自动答案。

## 2026-10-02 第二阶段切换

上文“不运行合并/压缩后处理”约束的是第一阶段。完整认证后自动进入冻结合同的第二阶段：原有批量/规则族/窗口/优先级提案优先；停滞后扩展完整观察窗口。有限邻域耗尽只报告搜索范围状态，不证明最短或全语言无解。

区域联合 SAT 与在线学习排序均已实现为可选入口。区域使用不同 donor 组轮转及逐步扩展，不冻结已匹配前缀；每条到达路径单独保留。学习只调整候选和策略顺序，保持探索，不能将未知反馈训练成失败。

固定案例没有显示区域或学习的净收益，因此默认不启用。实际测试暴露的424字退步路线已记录；默认保留原快速提案路线，长例仍为397字、325/325。当前切换依据、开销和失败路线见[2026-10-02执行记录](baselines/2026-10-02-exact-macro-workplan-execution.md)。

## 2026-10-04 宏库先验

新增离线真实反馈训练和匿名结构先验，模型载入新合同后冻结。它可以跨合同迁移数值权重、条件类别和连接符建议，不能迁移宏答案、前缀检查点、历史状态或标签。模型未知/不兼容时普通搜索继续。

昂贵候选生成器先产生最多16份提案供排序，而不是先生成整批；保留全部提案与探索。区域先构造有限条件库再做整规则联合选择，普通表达式和源条件完整保留，先验仅追加；时间叶不同仍保留独立唤醒来源。原自由链后端保留用于扩展，有限条件库UNSAT不是全语言无解。

独立预测指标有所改善，但325步案例仍397字，区域扩展增加回放/修补成本；默认不启用模型或区域。训练、验证、最终审计和真实worker证据见[宏库学习记录](baselines/2026-10-03-exact-macro-library-learning.md)。
