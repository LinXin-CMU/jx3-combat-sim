# 确定循环宏合成与压缩工作计划

日期：2026-10-02。项目：苍云器灵。状态：本轮最小工程与必要验证已完成；收益与未完成范围见执行记录。

本文汇总下一轮需要完成的算法、数据、机器学习、验证和交付工作。目标是把已有确定循环转成能够完整复现的条件宏，再自动压缩；算法应能处理不同循环、配置和初始宏，不依赖用户提供参考宏。

执行顺序是：先修正窗口与路径建模，再实现区域规则联合重写；同时采集和整理魔盒宏库语料。候选生成可靠后，接入轻量学习排序与策略调度。学习模型负责提出和安排候选，真实模拟器负责最终验收。

本轮已执行窗口与路径修正、区域联合重写、小批公开语料流程、可选在线学习模块及固定案例验证。长例保持397字完整通过，没有证明区域搜索或学习净收益，二者默认关闭。宏库来源尚未用于训练；多页通用求解、离线训练和跨场景收益评测尚未完成。源码交付与在线切换分开，未重启在线服务。具体实现、失败路线、数据量和实测见[本轮执行记录](baselines/2026-10-02-exact-macro-workplan-execution.md)及[宏库流程记录](baselines/2026-10-02-exact-macro-corpus.md)。下面的扩展计划不得全部作为已验证能力宣传。

## 1 目标和固定边界

### 两阶段目标

| 阶段 | 必须完成 | 不得混入的目标 |
| --- | --- | --- |
| 第一阶段提取宏 | 主动施放的技能、变体、顺序、次数、引导结果及约定时间容差全部通过 | 字符惩罚、DPS 接近、技能次数接近、重新生成更高 DPS 的动作序列 |
| 第二阶段压缩 | 沿用第一阶段冻结的场景与验收合同，缩短完整通过的宏 | 为了变短再次放宽容差、改变终点、丢弃辅助技能或放宽匹配标准 |

第一阶段不设字符数、规则行数、每行条件数或任务总运行时长上限。局部求解可以使用有限槽位和短时间片，并逐步扩展；这些是搜索安排，不是宏的永久表达限制。

第二阶段在第一阶段完整通过后自动进入。暂停、停止、搜索失败都保留已有候选与最后一份认证宏。停止后不继续计算；服务重启不恢复任务。

### 验收口径

- 当前网页合同为 `skills_and_time`：实际主动技能及变体、顺序、次数、引导跳数一致；每次施放相对原目标的绝对时间误差在合同容差内，不累计漂移。
- 当前默认容差为 62.5ms；第一阶段现有策略可在停滞时一次放宽至 125.0ms，并记录原因。进入压缩后立即冻结，不再放宽。独立实验也必须显式固定容差。
- 当前默认终点为末次目标主动施放后 125ms；显式配置终点时使用该值。终点附近的等待、额外施放及执行延迟按原执行器检查，不能截掉不利结果。
- 内部状态一致性单独报告。`skills_and_time` 通过不等于完整状态一致或 DPS 等价；选择 `skills_and_state` 的实验必须遵守其自身合同。
- 显示时间保留一位小数，验收使用原始精度。新增搜索阈值按当前一位小数规范生成；外部宏的原始精度保留，不能静默四舍五入后声称等价。
- 用户未提供参考宏 B 时也必须能运行。外部宏可用于离线学习和评估，生产请求不把 B 作为必填字段，不按目标检索一份现成宏作为答案。

本文的固定参考 B 指当前评测目标对应的武学助手宏。它及其同源变体保持隔离；其他合法采集的宏可以成为离线训练来源，二者不能混为一谈。

### 执行语义

继续复用原生选页、解析、技能池、可释放性、连招、GCD、网络延迟、等待与时间推进。`last_skill` 仍为上一次实际成功主动施放的基础名称；自动伤害事件不计入主动施放，主动辅助技能不能漏记。

`&` 与 `|` 等优先级且右结合。`A&B|C&D` 表示 `A&(B|(C&D))`，括号只用于解释，不作为新增宏语法。所有时间条件都可能影响调度，即使所在行最后没有被选中。

`/cast` 与 `/fcast` 的等价性依赖场景，尤其是引导。保留原生动作身份及可执行探测，不能对所有语料无条件替换。多页宏须保留页结构与选页规则；未支持的语法应明确标记，不能静默展平成单页。

### 4.2 窗口与路径

旧行命中只用于找到受影响事件。针对动作和插入位置，窗口引导集合为：

```text
该事件在本路径的已观测状态
∩ 固定前置规则之后仍可到达的状态
∩ 该动作可执行
∩ 该动作在该状态满足目标要求
```

新生成规则之间的遮挡由联合求解计算，不能提前固定给旧规则。AND 必须在同一个状态满足，不能分别拿窗口内不同状态为不同原子作证。

窗口只有已观测状态，不能声称枚举了全部连续时间。保守分支使用当前完整路径作静态引导；探索分支保留改变扫描时机的机会。任一分支的 UNSAT 都不能升级为全任务无解。

Rust 已提供 `truth`、`executable`、`allowed`、`cursor`、`wait_allowed`、`decision_latest`、`wait_next_time`、`wake_atoms` 和拒绝动作信息。需注意：

- `allowed` 是原生动作及时间预测，不证明施放后状态、引导结果或完整终点通过。
- `wake_atoms` 只在实际 WAIT 将跨过截止点时生成；空集合不证明不存在其他唤醒方式。
- compact 反馈不等于完整状态归档。普通搜索复用位集和必要字段，需要完整诊断时按需取得并留在后端。
- 只使用首次分歧前正确对齐的状态及首次失败决策。不同路径不无条件求并集，不给未到达后缀强加目标下标标签。

### 4.3 联合求解编码

每个规则槽位选择启用状态、动作、条件原子序列、`&/|` 连接符、长度与插入位置。空条件表示无条件规则。固定外部规则也参加完整首命中计算。

```text
hit(j,s) = enabled(j) ∧ condition(j,s) ∧ executable(action(j),s)
selected(j,s) = hit(j,s) ∧ 所有更早规则均未命中
selected(j,s) ⇒ action(j) ∈ allowed(s)
```

不能继续等待时必须有合法命中；每个未被外部规则接管的事件至少有一个合法窗口见证。允许等待不代表能够永远等待，仍须检查原生调度边和完整终点。

条件按原生右结合链编码和渲染，禁止输出解释用括号或新谓词。默认规则加例外通过同一个求解器实现：尝试底部无条件动作，同时联合求解上方接管规则。目标应等待的状态不能用额外动作遮挡，只能限制默认规则或依靠真实不可释放性。

第二阶段成本是最终可复制文本的 UTF-16 长度，包括命令、技能名、条件、分隔符、空格和换行。允许组合变换的中间步骤变长或单独不通过；整份候选必须重新认证，且只有更短的认证结果更新最佳宏。

先从小区域、少量槽位和条件开始，公平轮转后逐步扩展。保留 SAT、有限范围 UNSAT、UNKNOWN 和取消的独立状态。短时间片用于暂停响应，不作为任务总超时。

### 4.4 搜索速度与学习接入前的基础工作

复用常驻 oracle 和完整固定场景。分别记录候选构造、约束建立、求解、原生回放调用、反馈整理和归档耗时；无法从现有接口拆出的纯模拟时间应标为未分离，不能把调用耗时当模拟核心耗时。

新增样本、原子目录或验收合同变化时正确失效缓存。纯真值缓存可以复用，优先级、路径可达性和目标标签必须带上下文。候选正文未变不重复回放或网络推送；时间叶不同则不能仅按旧样本真值去重。

保留少量等长且完整通过、但状态或时钟来源不同的备用候选。每份备用候选使用自己的轨迹继续搜索；不恢复旧宏检查点，也不据施放指纹相同复用前缀状态。

| 数据层 | 可以用于 | 不能声称 |
| --- | --- | --- |
| 原始网页宏 | 追溯来源、待解析清单 | 语法合法、当前版本有效 |
| 已解析结构宏 | 条件结构、顺序和公共前提的候选先验 | 能在模拟器中执行或复现目标 |
| 对应版本可模拟宏 | 在明确完整场景下生成主动轨迹和决策样本 | 原作者的装备环境已被还原，或宏全局最优 |
| 合同下认证案例 | 训练候选排序、评估提取与压缩 | 对其他场景正确、证明全语言最短 |

缺少配置时，可以在项目已有测试场景中构造新的实验，但必须标为“项目构造场景”，不能冒充原作者配置。未知技能、Buff、语法或分页方式不得静默删掉后升级为可执行样本。

### 5.4 去重与防泄漏

保留文本哈希、原生语法树哈希和来源关系。格式不同、同一作者更新版、转载、派生改写、同源宏产生的轨迹和人工膨胀版本，都归入同一来源组。

按来源组和完整场景划分训练、验证、最终测试，不能按快照随机拆分。分组先于轨迹生成和数据增强。保留未见来源、未见配置的测试集；检查仅常量略变的近重复宏，不能只靠正文哈希。最终测试集不参与调参、特征选择或学习排序器训练。

当前 325 步武学助手案例及其同源变体作为固定对照，原则上不进入训练或规则先验提取。若后续研究明确使用其训练，必须更换未见测试集并披露，不能继续称其为未见验证。

### 5.5 自动构造训练任务

对兼容并通过原生验证的来源宏，在完整场景下生成目标主动轨迹。提取器只接收场景和轨迹，原宏正文对该次合成隐藏。来源宏提供一个已知可行长度上界，不提供最优长度标签。

在离线数据生产阶段，可生成候选删改、重排、分支重写、阈值变动和冗余版本，再用真实回放标注。只有验证通过的冗余版本才可作为“同目标、不同初始宏”的压缩样本。所有派生样本保持同源分组。

这种训练流程不要求真实用户提交参考宏 B，也不增加线上宏模板检索或跨任务现成答案复用。

## 6 机器学习的具体落点

### 6.1 规则学习服务于候选生成

借鉴有序规则列表与多标签决策树的组织方法，学习公共前提、条件作用范围、默认动作和例外分支。只使用宏支持的原子与连接方式。普通树的叶子路径可能引入不支持的否定、括号或错误的动作回退，因此树结构只作候选建议，仍需原生语法约束和整宏联合求解。

学习目标不能直接设为“所有快照分类正确”。标签必须包含可释放性、前置规则遮挡、允许动作和等待窗口。当前样本中同真值不等于不同未来路径上等价；条件来源和时钟差异保留探索名额。

结构学习不依赖大规模预训练即可先试。宏库先验只能调整候选生成顺序和结构偏好，不能硬编码“某技能一定看某 Buff”，也不能排除未在语料出现的合法表达式。

### 6.2 在线候选排序

先建立透明评分基线，再接轻量在线逻辑回归等模型。数据充分后才比较梯度提升树。每条试算记录至少保存：

```text
contract_hash / path_id / candidate_hash / source_group / oracle_version
generator_kind / feature_schema_version / model_version
pre_replay_features / predicted_score / exploration_choice
certified / chars_before / chars_after / first_difference_kind
matched_prefix / solver_status / timing_breakdown / cancelled
```

输入只用试算前可得信息，如候选长度、规则变化、窗口覆盖、优先级冲突、状态字段类型和时钟变化。试算后的匹配前缀可以作为反馈或后续搜索上下文，不能泄漏为该候选的事前特征。特征优先描述结构和条件类别，不以固定技能名或来源作者作为正确性捷径。

预测完整通过概率和验证成本，以预期认证收益安排顺序。失败要区分语义失败、求解 UNKNOWN、基础设施错误、暂停与取消，不能一律作为负例。静态筛选拒绝不能标成原生运行失败；截断、未完成认证及观察预算耗尽均保留未知状态。阶段一只学习推进复现的搜索偏好，不引入字符奖励；阶段二的主要收益来自完整通过后的字符减少。

模型只改变顺序，不硬删除低分候选。保留探索份额、来源多样性与无模型回退。样本不足或校准不佳时继续使用透明评分，不承诺训练后必然更快。

### 6.3 策略调度

评估上下文 bandit，在 window、family、joint、repair 等算子之间分配局部计算时间。上下文包含当前规则重复度、剩余复杂度、首次分歧类型、近期认证收益与耗时。

奖励优先使用认证后节省的字符及计算成本；保留对等长认证新路径和暂时无收益策略的探索。每个最佳宏更新后搜索环境会变化，需要更新或衰减旧统计，防止早期表现永久决定后续优先级。

该模型选择搜索操作，不生成新的技能循环。PPO、大型序列模型、未经验证的宏全文生成暂不列为近期主线。

## 7 必要验证和实测口径

遵循“只做必要测试”。新增独立回归放在 `backend/tests/`。只改 Python 搜索和文档时，不为此重复无关 Rust 全量测试；若实际改动 Rust 行为，则遵循仓库相应验证要求。

### 必须覆盖的边界

1. 原生混合 AND/OR 右结合、公共门槛和分支门槛，渲染后语义保持。
2. 窗口里至少一个同状态见证；不能把不同快照拼成 AND，也不能强迫全窗口处处释放。
3. 不可释放动作、前置正确动作遮挡、默认规则与 WAIT、截止点和终点额外施放。
4. 同动作 2→2、跨旧行重分工及跨动作优先级联合修改，中间操作无需分别通过。
5. 相同真值、不同唤醒阈值的候选不被错误合并。
6. 候选专属路径、宏行号与首次分歧；不合并互斥路径或标注跑偏后缀。
7. UNKNOWN、取消、停止、完整认证门控；暂停不走有效运行秒数，停止不遗留持续搜索。
8. 语料版本/分页/手动动作缺失、同源去重和训练测试泄漏检查。

另做小规模原子目录重排与等成本标识置换检查，观察结果是否过度依赖偶然排序。真实技能名字长度属于字符成本，不能用改变名字长度的实验假装证明算法对标识完全不敏感。

### 端到端案例

先保留当前 325 步固定案例，从 3110 字、较短认证宏及其他已验证结构起点分别压缩，比较算法是否过度依赖初始拆行。再加入兼容的铁骨案例、等待敏感案例，以及确实涉及引导和多页的范围诊断；超出当前求解范围应明确返回限制，不能假装完成。

未见测试从语料中按组预留，优先覆盖项目实际支持的版本和心法。数据规模由可用性决定，先报告真实覆盖，再逐步扩充；不把一个循环的数千个相邻快照当成数千个独立场景。

### 对照实验

| 对照 | 要回答的问题 |
| --- | --- |
| 当前默认算法 | 保留速度与结果基线 |
| 加窗口修正与区域联合重写 | 候选结构扩展本身带来多少收益 |
| 再加规则结构建议 | 规则学习是否改善长度或到达速度 |
| 再加候选排序 | 是否减少达到同长度所需的回放 |
| 再加自适应调度 | 是否减少无收益策略耗时 |

实验固定硬件、场景、合同与明确的离线评测观察时长；产品仍无任务总时限。报告首次完整复现时间、到达指定认证长度的时间、认证最佳长度随时间曲线、试算次数、重复候选比例、完整通过率，以及构造/求解/回放/学习开销。少量重复观察波动，不能用一次偶然最快值宣布提速。

跨案例汇总时同时报告失败和未改善案例。达到观察时长但未达到目标长度记为未达到，不改算成功。模型按完整来源/场景分组验证，训练时间和推理成本计入总成本。

## 8 运行体验与数据流保持要求

- 每份新的待测宏生成后进入当前试算预览；最佳宏只有认证通过后更新，保持现有差异提示。
- 暂停保留当前预览与计算进度，停止及时中断。不要通过高频完整刷新造成页面卡顿。
- 正文哈希不变时不重复传宏。浏览器只接收必要状态和宏；原始语料、训练特征、轨迹、约束、模型诊断和完整结果包留在后端，不提供用户下载。
- 不新增无关 UI 组件。默认保留简单的运行、暂停、停止、最佳宏和当前试算入口。
- 用户循环和配置继续按 worker 隔离。数据生产与实验使用隔离测试目录，不写真实用户的循环、宏或会话。
- 不引入未经等价证明的前缀检查点恢复，不恢复用户已经明确不保留的服务重启任务。

## 9 失败分类与完成判定

| 情况 | 应记录的结论 |
| --- | --- |
| 原生宏与手动目标执行语义未对齐 | 语义或目标构造问题；先修复，不归咎求解器 |
| 外部宏含未知版本、动作或语法 | 语料不兼容或配置缺失，保留原文与原因 |
| 当前条件目录或局部槽位 UNSAT | 当前候选范围无解，扩充或换区域；不称全语言无解 |
| 求解超时或 UNKNOWN | 当前求解未得出结论 |
| 候选完整回放失败 | 该候选不满足合同，记录首次分歧及其路径 |
| 搜索范围耗尽 | 本轮邻域没有新结果，不证明最佳宏最短 |
| ML 没有净收益 | 保留无模型默认，记录适用范围，不用分类准确率替代实际收益 |
| 两观测状态不可区分却需求冲突 | 输出当前原子、可执行性、页和路径范围内的证据；不足以自动证明完整任务无解 |

本轮工程完成必须交付：可运行的新搜索入口、必要回归、固定案例对照、语料清单和分组规则、学习模块开关及版本记录、失败案例、更新后的说明与可复现实验参数。若尚未得到更短结果，要明确区分“能力已实现并验证”和“压缩收益未证明”。

不设“必须压到 358 字”作为预设成功结论；目标是提高通用性、认证结果质量和达到结果的速度。具体量化收益由本轮实测填写。
