# 第 0 阶段执行计划：可安全公开的作品集基线

更新日期：2026-08-25  
计划工期：2 个工作日  
阶段目标：在不改变战斗数值和玩法行为的前提下，把当前本地项目整理成一个可审查、可复现、不会泄露凭据的作品集仓库基线。

执行状态（2026-08-25）：本地工程项已完成并进入最终复现审计；旧部署保持停用。公开远端、首次 push、未来部署凭据和作品集素材仍受 `docs/RELEASE_CHECKLIST.md` 阻断。

## 1. 完成定义

只有同时满足以下条件，第 0 阶段才算完成：

1. 仓库中不存在真实密码、隧道密钥、会话令牌、用户数据或本机配置；已公开在明文资料中的部署凭据在实际服务端失效，而不只是从文件中删掉。现有用户与会话数据保留在本机忽略目录中。
2. `.gitignore` 能排除 Rust 构建物、Python 环境、RL 模型与训练日志、用户数据、日志、发布产物和真实部署配置。
3. Git 首个基线提交在秘密扫描通过后产生，`git status` 干净，陌生人可以审查后续提交。
4. Windows 本地启动入口统一为 `http://localhost:3005`，启动后 `/health`、首页和至少一次模拟请求可用。
5. 根目录 README 能让招聘者在 3 分钟内理解项目定位、核心能力、架构、运行方式、验证方式和当前 Agent 路线；尚未实现的 Agent 不得写成已完成能力。
6. 当前单元测试、确定性 golden、前端语法和性能基线均有带日期的记录，并能按文档复现。
7. release checklist 可以阻止“秘密未轮换、测试未通过、Demo 不可用”的版本被公开。

阶段产物不是 Agent 功能，而是后续 Agent 开发可信、可展示、可回滚的地基。

## 3. 执行原则与顺序

执行顺序必须是：

```text
只读盘点
  → 建忽略规则和安全样例
  → 轮换外部凭据并让旧值失效
  → 清理工作区中的真实值与用户数据入口
  → 秘密扫描
  → 初始化 Git 和首个提交
  → 修复启动口径、README 与验证记录
  → 最终扫描和发布验收
```

禁止直接对当前目录执行 `git add .`。`.gitignore` 不是秘密管理工具：如果真实值进入过提交，即使后来删除也要按已泄露处理并清理历史。

## 4. 工作包

### P0-01 只读资产与秘密盘点

目标：明确哪些内容可以公开、哪些必须样例化、哪些必须留在本机。

执行：

- 枚举发布脚本、frp 配置、运维文档、用户白名单、用户工作目录、日志、RL checkpoint、TensorBoard 数据、构建产物和本机虚拟环境。
- 只记录“文件路径、秘密类型、轮换状态和负责人”，不在新文档中复制秘密值。
- 将凭据分为：公网登录主密码、frp 双端共享密钥、现存会话令牌、服务器登录凭据、未来模型 API Key。
- 判断公开范围：源码和小型规则数据纳入仓库；模型权重、训练日志、用户数据、发布二进制和真实连接配置排除。

交付：`docs/security/SECRET_ROTATION_CHECKLIST.md`，只含脱敏条目与状态。

验收：每一种敏感材料都有明确的“轮换、删除、样例化或忽略”归宿，不存在“暂时先提交”的项目。

### P0-02 建立忽略边界与安全配置样例

目标：先建立不会误收本机状态的文件边界。

计划新增或调整：

- 根目录 `.gitignore`；
- `.env.example`，只保留变量名和安全占位符；
- `tools/frpc.example.toml`，不含真实地址和密钥；
- 如白名单结构需要展示，提供无真实用户名、令牌和密码摘要的 example JSON；
- 发布脚本改为读取环境变量或私有配置，缺失时明确失败，不提供弱默认值。

至少忽略：

- `backend/target/`、`dist/`、`.venv/`、`__pycache__/`；
- `backend/userdata/`、日志、临时文件；
- `python/runs/`、`python/pretrains/`、模型权重、TensorBoard 事件；
- `.env` 及其本地变体、真实 frp 配置、私钥和证书；
- IDE/系统缓存与临时打包目录。

验收：用 `git check-ignore -v` 对每类代表文件验证；example 文件能够说明配置结构，但扫描不到任何真实值。

### P0-03 轮换并撤销真实凭据

目标：让当前已经出现在本地明文中的旧凭据真正失效。

执行顺序：

1. 生成新的高熵公网登录主密码和 frp 共享密钥，存入系统环境变量或仓库外的私有配置。
2. 同步替换 frp 服务端和客户端配置，先验证新连接可用，再确认旧密钥无法连接。
3. 替换公网应用主密码。保留现存成员、个人密码摘要和会话令牌，并验证已有用户仍可使用；只有发现会话令牌曾离开本机或出现在公开历史中时，才另行请求确认后撤销。
4. 若运维文档中涉及服务器登录凭据，按已暴露处理并轮换。
5. 为未来模型 Key 预留环境变量名，但第 0 阶段不接入、不创建真实模型 Key。

旧部署分支：用户已确认旧部署当前未使用，但需要保留部署功能。因此本阶段不连接旧 VPS；旧值从公开文件和可执行脚本中退役，Cloudflare/frp 流程改为参数化。未来重新部署时必须生成全新的登录主密码与 frp 双端密钥，不能复用旧配置。

验收：新部署凭据能完成健康检查，旧部署凭据失败；已有用户和会话状态保持可用；源码和文档只引用变量名，不出现值；验证日志不得打印秘密。

### P0-04 清理公开文件并执行秘密扫描

目标：把真实部署资料转为可公开、可复用的说明。

执行：

- 从发布 PowerShell、VPS 初始化脚本、frp 配置和运维手册中移除真实值、真实入口和个人账号信息。
- 将命令示例改成 `<YOUR_...>` 或环境变量引用。
- 用户数据目录原样保留在本机并整体排除，不逐个挑选所谓“无害”的用户文件，也不因仓库清理而重置会话。
- 对工作区执行两层扫描：高风险关键词/格式扫描，以及专业秘密扫描工具；如工具暂不可用，关键词扫描为阻断项，专业扫描记录为首次公开前阻断项。
- 对命中结果逐项判定，业务中的 `token` 变量、技能秘籍 ID 等允许保留，但必须说明为什么不是凭据。

验收：零个未解释的高置信秘密命中；扫描报告只记录文件和规则，不回显秘密全文。

### P0-05 初始化 Git 安全基线

前置：P0-02、P0-03、P0-04 已通过。

执行：

- 初始化 Git，默认分支使用 `main`；
- 检查 `git status --short --ignored`，确认大模型文件、用户数据、构建目录和真实配置均未进入暂存区；
- 首个提交只表达“现有模拟器的安全基线”，不伪造过去开发历史；
- 建议提交结构：
  1. `chore: establish safe repository baseline`；
  2. `docs: add portfolio-facing project overview`；
  3. `fix: unify local startup entrypoint`；
  4. `test: record phase-zero regression baseline`。
- 是否添加开源许可证单独决策。未明确授权他人复用前，不随意套用许可证。

验收：提交后工作区干净；对 `git ls-files` 再做一次秘密和大文件扫描；仓库历史中不存在轮换前的凭据。

### P0-06 统一本地启动与健康检查

决策：普通本地体验采用后端单进程入口。Rust 服务已经通过 `ServeDir` 托管 `frontend/`，因此 `start.bat` 只启动后端并打开 `http://localhost:3005`。

执行：

- 修正 `start.bat` 的进程数、提示、等待和浏览器地址；
- 保留环境变量覆盖端口的能力，文档明确默认值；
- 如果以后需要前后端独立调试，另设名字明确的开发脚本，不把它作为招聘者快速体验入口；
- 增加或记录最小 smoke 流程：启动、轮询 `/health`、加载首页、调用一个稳定的轻量模拟场景、正常退出。

验收：新环境按 README 执行一个命令即可访问；不存在 8080/8081 的错误提示；进程失败时脚本不给出成功假象。

### P0-07 建立作品集 README 与素材结构

目标：让技术面试官和策划面试官都能快速找到证据。

README 固定结构：

1. 一句话定位与主视觉；
2. 90 秒体验路径；
3. 已实现能力与明确边界；
4. 系统架构图；
5. 代表性策划问题和验证证据；
6. 快速启动、依赖和测试；
7. Game × AI 路线图：将 Agent 标为“规划中/开发中”，不冒充成品；
8. 技术选型、个人职责和设计取舍；
9. 已知限制、版权/非官方声明和文档索引。

素材目录建议：

```text
docs/portfolio/
  images/       # 压缩后的公开截图
  demos/        # GIF/视频链接说明，不直接提交超大视频
  cases/        # 后续战斗分析与 RL 蒸馏案例
```

第 0 阶段只需要截图清单和占位规范，不为凑页面临时制作低质量素材。截图不得包含用户名、公网地址、Cookie、日志令牌或本机绝对路径。

验收：陌生读者无需打开源码即可回答“这是什么、解决什么策划问题、如何验证、如何运行、AI 做到哪一步”。

### P0-08 固化测试、golden 与性能基线

目标：建立 Agent 接入前的行为锚点，未来能证明 AI 改造没有破坏模拟器。

基线矩阵：

| 层级 | 命令/对象 | 通过标准 |
|---|---|---|
| Rust 单元测试 | `cargo test`（`backend`） | 全部通过；记录测试数和 warning 数 |
| 前端语法 | `node --check frontend/app.js` | 退出码 0 |
| 确定性回归 | `backend/tests/diff_baseline.py` | 同请求重复一致、lite/full 一致、4 个 golden 一致 |
| 回归总入口 | `backend/tests/run_regression.sh` 或等价 Windows 步骤 | 各阶段无失败 |
| 性能 | `backend/PERF.md` 指定固定场景 | 记录硬件、构建模式、输入、重复次数、中位数和 P95 |
| 启动 smoke | `/health`、首页、固定轻量模拟 | 全部响应成功，输出 fingerprint 稳定 |

规则：

- 第 0 阶段不得使用 `--update` 掩盖 golden 漂移；若发现漂移，先诊断再决定是否属于旧基线问题。
- 性能记录区分 debug 与 release，作品集只引用可复现的 release 数据。
- 测试输出写摘要，不提交包含个人路径或运行令牌的完整日志。

交付：`docs/baselines/2026-08-25-phase0.md`，包含环境、命令、结果、fingerprint 摘要和已知 warning。

### P0-09 Release checklist 与阶段验收

新增 `docs/RELEASE_CHECKLIST.md`，至少包含：

- 秘密已轮换、旧值已失效、扫描通过；
- `git status` 干净，忽略规则抽查通过；
- 单元、语法、golden、smoke 和性能基线完成；
- README 中能力状态真实，链接有效；
- 截图和 Demo 不泄露个人信息；
- 公网体验若开启，使用 HTTPS、强鉴权和最小权限；否则 README 明确只提供本地运行；
- 版本号、变更摘要、回滚点和已知限制已记录。

验收：逐项勾选后才能创建公开远端或发布作品集链接。

## 6. 风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| 无法连接现有 VPS/frp 服务 | 不能证明旧凭据已经失效 | 关闭外部入口并记录，恢复连接后再轮换；在此之前不公开仓库 |
| 用户数据被误加入 Git | 会话或隐私泄露 | 整体忽略 `backend/userdata/`，首提交前检查 `git ls-files` |
| 大模型文件进入仓库 | 仓库膨胀，可能触发托管限制 | 忽略 checkpoint/runs，只保留小型 spec 与复现实验说明时也需逐项审核 |
| golden 在未改业务时漂移 | 暗示环境或确定性问题 | 停止更新 golden，固定版本/环境并诊断 |
| README 宣传超过实际能力 | 面试追问时失信 | 明确区分“已实现、开发中、路线图” |
| 为清理而重构大文件 | 扩大回归面、拖延 Agent 主线 | 第 0 阶段只做安全、启动、文档和验证，不拆 `main.rs/app.js/style.css` |

## 7. 明确不在第 0 阶段做的事

- 不接入模型 API，不实现聊天 UI 或 Agent 工具循环；
- 不调整技能、Buff、奇穴、秘籍、伤害公式或 RL 奖励；
- 不重训 PPO/BC，不提交现有模型权重；
- 不重构三个超大源文件；
- 不把裸 HTTP 公网入口包装成正式 Demo；
- 不为了好看伪造历史提交、测试结果或已实现能力。
