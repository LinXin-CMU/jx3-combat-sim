# 确定循环 → 条件宏

更新：2026-10-01。入口为循环模拟的器灵浮窗「循环合成」。原宏生成器、写宏助手、GA、RL 保留。本功能不调用语言模型，不以 DPS 或技能次数近似作为通过标准。

## 两阶段合同

第一阶段先生成完整复现目标主动施放的宏，不设字符、规则行数、每行条件数或任务总运行时间上限。当前默认策略使用有序 AND 规则构造和真实回放反例；有限原子目录、单页语言与观测范围仍是算法边界，不代表搜索完备。

第二阶段在第一阶段通过后自动压缩。每次压缩沿用第一阶段最终冻结的配置、目标、终点及时间容差，从零开始真实回放。只有完整通过且可复制正文更短，才更新最佳宏。暂停、停止、失败都保留最后一份已认证宏。第二阶段不再次放宽验收，也不读取武学助手预设或要求用户提供参照宏 B。

当前网页默认验收 `skills_and_time`：主动技能及变体、顺序、次数、引导跳数一致；每次施放与其原目标的绝对时间误差在所列容差内，不累计漂移。默认容差 62.5ms；第一阶段搜索停滞时可一次放宽至 125.0ms并记录原因。内部离散状态独立诊断，不能将此合同通过表述为完整状态一致。显示保留一位小数，验收使用未四舍五入的数值。

默认终点为末次目标主动施放后 125ms；此前全部等待及额外施放仍参与验收。允许在终点处决策，执行延迟导致的终点后施放也不裁剪。CLI 可提供明确场景，原型策略会记录实际采用的终点。

## 真实执行语义

- `last_skill` 是上一次实际成功的主动施放基础名，按 `·` 前名称更新。扫描宏行时不更新，不把自动伤害事件当作主动动作，辅助主动技能也计入轨迹。
- 先由原生选页器确定页面；Phase 1 按源顺序收集条件成立的技能，Phase 2 按顺序检查实际可释放性及连招解析。首个合法命中才能执行。
- 错误动作不可释放，或排在正确命中之后时，条件成立可以合法。负样本约束不能把这些情况一概强制为假。
- `&` 和 `|` 等优先级且右结合。例如 `A|B&C|D` 表示 `A|(B&(C|D))`。没有自创括号语法，不能按其他语言的优先级渲染表达式。
- `/fcast` 不跳过 GCD/CD。它影响引导打断；没有引导的场景只生成 `/cast` 动作目录。有引导时分别探测 cast/fcast 的真实行为。
- 条件命中、技能充能、GCD、网络延迟、等待与时间推进由同一 Rust 执行器计算。所有宏行中的 Buff 时间阈值都会影响下一次扫描时刻，即使那行最终未被选中。
- 连招母按钮和显式分段动作是否可替代，由原生解析和每个状态的合法动作集合决定；不建立手工技能别名表。

## 第一阶段的等价条件

同一个状态通常有多种可用判断，生成结果并不唯一。例如正常非负 Buff 层数下，`nobuff:嗜血` 与 `buff:嗜血<1` 可以表达相同含义。还有一些条件只是在当前采样状态上真假相同，不能据此认定其运行等价。

构造器按当前全部真值列暂时归组，保留完整母目录。变体可选择不同代表；新增反例后重新划分，不永久删除别名。每行只保留当前样本所需的区分判断；这是候选构造，不是第一阶段的字符优化目标。

行内两个判断都为真不等于冗余。删条件、换代表或调整顺序可能造成抢先释放，Buff 时间条件还可能改变调度；候选必须交给真实执行器复核。

## 第二阶段默认搜索

按成本依次尝试批量删除/合并、条件替换、OR 合并、同动作子集的多规则重建、原生混合链和跨位置联动重建，再尝试小窗口 SAT 与有限优先级分支。

`exact_macro_conditions.py` 使用原生右结合链搜索短条件，保留不同唤醒阈值的候选并缓存当前样本实例内的真值查询。`exact_macro_reorder.py` 将条件替换、规则移动和规则删除组成一次待测变换；中间操作不需要单独通过。动作替代从原生 allowed/executable 集合推导。

`exact_macro_family.py` 自动识别同动作的重复规则，联合选择 donor 子集、多个替代条件和插入位置。它允许把多条规则重建为两三条，让同一技能保留不同优先级位置；不要求一个技能最终只写一条。候选按动作与结构轮询保留，避免最便宜的一组独占回放名额。位集、候选数和搜索展开额度只控制本次邻域探索，不限制第一阶段的宏行数或任务总时长。移除 donor 后可能抢错动作的其他规则必须由更早的替代规则保护；不可释放动作不构成负样本，WAIT 状态仍参与筛选。所有候选继续经过原始合同下的真实回放认证。

小窗口 SAT 的 SAT 仅代表当前样本见证；UNSAT 仅适用于该窗口及候选集；UNKNOWN/超时单独记录。默认搜索范围耗尽为 `scope_exhausted`，不证明全语言无解或全局最短。

跨技能联合重建为独立研究入口 `--compress-joint`，也包含在 `--compress-deep` 中。`exact_macro_joint.py` 按实际可执行命中冲突自动选择多个动作的规则区域，联合构造原生 AND/OR 条件与优先级，已有 OR 规则不再跳过。反例修复沿失败候选继续，允许宏比该候选变长，但完整结果必须短于已认证最佳宏。修复优先保留原结构；尚未在该路径被选中的规则只作为可选候选保留，不添加未来状态标签或永久冻结规则。

完整源轨迹与成功窗口投影分开生成候选；真正到达的 WAIT 反例不得从投影删除。每个反例分支只含其首次分歧前已对齐的原生状态，不合并不同路径。条件、动作和时间条件的样本表现均不能替代完整认证。当前长例该研究入口仍未缩短 518 字认证宏，网页默认关闭，以免增加无收益回放。详见 `docs/baselines/2026-10-01-exact-macro-joint-search.md`。

新增的整份宏重建仍为研究模式：CLI 使用 `--compress-deep` 启用。它会尝试位集 beam 和最多 12 个独立反例分支，不固定原规则前缀。每个分支只保留该次候选首次分歧前已对齐的状态及真实 WAIT；不加入旧宏尚未到达的后缀状态，也不把不同失败路径累积为统一硬约束。该模式尚未在当前长例改善已认证结果，因此网页默认不运行，避免额外的无收益回放。

## 回放、预览和数据

Rust oracle 是常驻本地进程，固定场景准备可缓存。失败候选在首次确定分歧处提前返回；成功候选另外进行完整目录、完整终点认证。完整条件真值以位集输出，普通压缩失败先只观察一列；整份重建需要反例时再观察完整目录，不能把一列筛选结果当作全部真值。

每个待测宏都发布预览；最佳宏只在认证通过后更新。页面可切换当前试算和最佳宏，并提示正文变化。暂停冻结有效运行时间，停止中断回放。刷新可恢复当前 worker 任务，服务重启不恢复任务。

完整结果包仅存 `backend/target/exact-macro-records/<job-id>/`，供后端测试留档；不提供用户下载，不经 HTTP 传输。浏览器仅接收宏及必要状态，正文 SHA-256 不变时不重复发送。循环配置按用户 worker 隔离。

## 运行与验证

先构建后端，再安装独立 Python 环境：

```powershell
python -m venv .venv/exact-macro
.venv/exact-macro/Scripts/python -m pip install -r tools/requirements-exact-macro.txt
cd backend
cargo build --release
cd ..
.venv/exact-macro/Scripts/python tools/exact-macro-synth.py backend/tests/fixtures/exact_macro_short.json --exe backend/target/release/jx3-combat-sim.exe --out backend/target/exact-short
```

后台可用 `JX3_EXACT_PYTHON` 指定依赖齐全的解释器。oracle 在加载真实用户设置之前进入本地协议，不读写真实 userdata。第一阶段与第二阶段都保留本地场景、条件、规则、比较及求解状态证据。

当前结果及失败路线见 [原生条件搜索记录](baselines/2026-10-01-exact-macro-native-search.md) 与 [同技能多规则重建记录](baselines/2026-10-01-exact-macro-family-search.md)。文中的性能是单个固定案例实测，不代表所有循环或多人负载。
