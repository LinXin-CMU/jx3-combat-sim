# Agent v20：面向循环诊断的可验证推导架构

## 问题

v19 已能限制工具、冻结场景、登记证据并校验报告数字，但仍可能出现三类问题：

1. 用“调用了时间轴工具”代替“完成了循环诊断”；
2. 从一个风险信号直接跳到修改方案，缺少可反驳的因果假设；
3. JSON、数字和引用合法，但答案没有回答玩家真正的问题。

v20 的目标不是展示模型的私有逐 token 思维，而是展示一条可审计、可复现、可评测的专业推导轨迹。

## 参考方法与取舍

- [ReAct](https://react-lm.github.io/) 将推理与环境动作交错，适合在新证据返回后更新计划。本项目用它组织“检查点 → 工具 → 证据状态更新”，但不展示私有思维文本。
- [Anthropic：Building effective agents](https://www.anthropic.com/engineering/building-effective-agents) 强调从简单组合模式开始、保持透明、认真设计工具接口，并只在评测证明有效时增加复杂度。本项目因此保留一个 Agent，不引入多 Agent 角色表演。
- [Tree of Thoughts](https://proceedings.neurips.cc/paper_files/paper/2023/file/271db9922b8d1f4dd7aaef84ed5ac703-Paper-Conference.pdf) 说明在需要探索和回看时可以维护多个候选思路。本项目仅在“循环优化的竞争性因果假设”处采用受限分支：最多三个假设、一个实验，避免全流程搜索造成成本和空转。
- [Reflexion](https://arxiv.org/abs/2303.11366) 使用语言反馈和情景记忆改进后续尝试。本项目先把批判结果写入私有复现轨迹；只有经过固定题集或人工标注验证的失败模式，才会进入长期规则，避免一次错误会话污染领域知识。
- [OpenAI Model guidance](https://developers.openai.com/api/docs/guides/latest-model) 建议为工具阶段明确任务、工具、输出、证据、重试、停止与交接条件，并将最终答案质量与工具执行结果分别评估。本项目把这些条件编码成 `reasoning_state` 和语义发布门禁。
- [Anthropic：Demystifying evals for AI agents](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents) 建议结合确定性、模型和人工评分，同时阅读完整轨迹，不要用僵硬的固定调用顺序惩罚有效路径。本项目校验“产出了什么、证据是否足够”，而不是要求模型严格按唯一工具序列运行。

## v20 运行结构

```text
用户问题
  ↓
问题框定：版本 / 心法 / 输入方式 / 用户决策
  ↓
Reasoning State：逐项列出要回答的判断与证据状态
  ↓
最小下一动作 ──→ 只读工具 ──→ 更新证据与检查点
  ↓                                  │
循环画像：伤害结构 / 节奏 / 资源 / 姿态 / 覆盖 / 跳过输入
  ↓                                  │
已验证优点 → 可观察风险 → 当前攻略约束
  ↓                                  │
可反驳假设（最多 3 个，选择 1 个） ←─┘
  ↓
同场景单变量实验（仅优化任务）
  ↓
接受 / 拒绝 / 保留假设
  ↓
结构与数值校验
  ↓
语义批判：任务完成度 / 证据归属 / 因果 / 范围 / 干预必要性
  ↓
发布玩家可读结论，或仅用已有证据修订一次
```

## 循环模拟检查点

| 检查点 | 必答问题 | 最低证据 | 禁止捷径 |
|---|---|---|---|
| 锁定口径 | 哪个版本、心法、输入方式、冻结环境？ | 场景快照 | 从问题措辞猜场景字段 |
| 输出画像 | 当前伤害、技能、节奏、资源与姿态结构如何？ | 基线 + 时间轴 | 只报 DPS 和总伤害 |
| 已验证优点 | 哪些部分确实稳定工作？ | 时间轴诊断 | “无空档”等于“最优” |
| 可观察风险 | 哪里可能限制循环？ | 时间轴诊断 | 怒气触顶等于已测损失 |
| 攻略约束 | 当前版本理想循环如何解释现象？ | 版本匹配资料 | 用攻略代替当前实测 |
| 因果假设 | 最值得测试的原因是什么，什么会推翻它？ | 时间轴 + 攻略 | 从风险信号直接写改法 |
| 单变量实验 | 候选改变了什么，结果支持假设吗？ | 同场景对比 | 多变量改动后单因归因 |
| 发布检查 | 是否回答问题且没有越过证据？ | 完整证据图 | JSON 合法即视为专业答案 |

## 可见轨迹与私有记录

前端可见：阶段目标、当前检查点、工具动作、证据数量、公开决策摘要、批判结果和错误码。

私有复现记录：完整输入、供应商响应、工具参数与结果、每次 `reasoning_state`、被拒报告和校验原因。它用于开发调试，不直接展示供应商的隐藏推理内容。

## 发布语义门禁

v20 在原有结构、数字和引用校验之外，增加以下确定性规则：

- 当前循环诊断必须实际引用本轮时间轴证据；
- 发布任何宏或手动循环改法，必须存在并引用同场景对比；
- 配装答案必须使用当前配装工作区；
- 当前配装检查不得擅自引入用户没有询问的“四切糕”等策略分支。

这组规则刻意校验结果而非唯一工具顺序。后续模型型 grader 将用于判断更主观的“专业度、完整性和说人话”，并由固定题集与人工样本校准。

## 评测计划

1. 回归题：原有工具、版本、会话、安全与数值校验必须接近满分。
2. 能力题：循环基线、空转诊断、宏优化、手动循环、保存宏对比、配装咨询分别设置困难样例。
3. 每题至少评分：任务完成度、工具/证据正确性、领域推导、因果克制、可执行性、表达、成本与延迟。
4. 非确定性模型题运行多次，记录通过率而不是单次成功截图。
5. 定期人工阅读完整脱敏轨迹，区分 Agent 错误与 grader 误杀。
