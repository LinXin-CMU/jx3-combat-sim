# Agent 模型上下文预算

## 问题

旧实现把完整工具结果追加到模型对话，并在后续轮次重复发送此前所有消息。完整证据虽然适合后台复现，却不适合作为每轮模型上下文：时间轴中的 Buff 区间、技能明细、知识片段、分析计划和模型草稿会持续累积。

失败样例 `run-1a0602f5db2-3` 的第三轮紧凑序列化请求约为 85,521 bytes，最终收到供应商 HTTP 400。该轮还存在路由误判：问题中的“不要在诊断前直接给修改方案”被裸关键词“修改”识别成了明确优化请求，导致已经完成诊断后又追加一次无意义模型调用。

## 分层设计

```text
工具原始结果
  ├─ 完整证据层：不可变保存，供复现、数值校验、引用校验使用
  └─ 模型投影层：裁剪高基数数组和冗余字段，保留判断所需事实与证据 ID
          ↓
当前证据包 + Reasoning State
          ↓
请求总字节检查（72 KiB）
  ├─ 未超限：发送
  └─ 超限：丢弃旧供应商 transcript，重建紧凑交接上下文
              ↓
        再次检查；仍超限则本地截停并发布已有证据
```

## 硬约束

- Provider-neutral `ModelRequest` 最大为 73,728 bytes；协议层和编排层同时检查。
- 单个模型可见工具结果最大为 16 KiB。
- 紧凑证据交接的首选预算为 24 KiB；必要时依次降到 12 KiB、6 KiB。
- 超限请求不会发送给供应商。后台完整证据不被删除或覆盖。
- 每次模型请求在私有复现记录中登记实际 `request_bytes`、上限、消息数和工具数。

## 投影规则

- 时间轴：删除 Buff 的完整区间列表；保留覆盖率、激活次数、诊断汇总、资源与姿态信息；空档和冷却等待只保留少量定位样本。
- 知识检索：保留标题、章节、限长正文片段、版本匹配、来源链接、领域声明和人物关系；删除排序中间分数。
- 场景：保留版本、心法、属性摘要和已解析宏语义，不携带重复的长序列。
- 场景对比：保留候选、总量变化和按伤害变化排序的主要技能差异。
- 其他工具：递归限制长字符串、数组长度和嵌套深度；超限时退化为核心事实摘要。

## 失败保全

如果供应商在后续轮次失败，编排器先尝试从此前模型草稿恢复并重新执行报告校验；无法恢复时，使用已登记的本地证据发布 `partially_verified` 报告。只有第一轮失败且没有任何可发布证据时，才返回 `provider_failed`。

## 真实验收

同一问题和同一场景重新运行：

- 原失败：`run-1a0602f5db2-3`，第三轮约 85,521 bytes，`provider_http_400`。
- 修复后：`run-1a0607e7177-0`，状态 `completed`。
- 三次请求分别为 47,479、61,137、61,388 bytes，均低于 73,728 bytes。
- 路由不再要求候选对比；本轮只完成场景、知识与时间轴诊断。
- 第二轮供应商曾返回空响应，但有界重试成功，没有丢失已取得证据。

上述上限约束由单元测试、完整回归和真实供应商运行共同覆盖。

显式“诊断 → 单变量候选 → 同场景对比”压力验收：

- 修复前：`run-1a06080e4e8-1` 虽已把后续请求稳定压到 59,467 bytes，但模型在取得对比证据后仍反复请求模拟，最终耗尽工具预算。
- 最终修复：`run-1a060884e74-0`，状态 `partially_verified`；部分通过原因是报告指标校验差异，不是上下文或供应商失败。
- 三次模型请求分别为 48,601、65,788、55,955 bytes；最后一轮通过紧凑交接重建上下文。
- 工具链只执行场景读取、知识检索、基线模拟、时间轴诊断和一次场景对比，共 5 次调用、3 次模拟。
- `compare_scenarios` 完成后触发 `single_variable_comparison_completed`，最终请求暴露 0 个工具，不再重复模拟或耗尽预算。
