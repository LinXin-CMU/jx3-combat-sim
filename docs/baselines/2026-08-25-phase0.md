# Phase 0 回归与性能基线

记录日期：2026-08-25

基线提交：`f4c9e13`（`chore: establish safe repository baseline`）

结论：核心模拟结果具备进程内确定性，Lite/Full 结果一致；但当前 golden 有 2 个历史漂移，静态状态写入守卫有 3 类违规。在完成诊断前，本基线不能作为“全部通过”的公开发布证据。

## 4. 状态写入守卫

守卫发现：

- 10 处直接写入 `player.rage`，均位于 2025 版本脚本；
- 3 处直接写入 `player.block_value`，其中 1 处位于当前 2026 版本；
- 2 处直接插入 `active_cds`，其中 1 处位于当前 2026 版本。

这些写法可能绕过 `bump_decision_gen()`，使宏条件缓存与实际状态不同步。替换为 setter 可能改变 fingerprint，因此它属于需要单独回归、不能在 Phase 0 中静默处理的行为修复。

## 5. Release 性能基线

场景：`tests/diff_baseline.py` 的“绝云宏 standard”，300 秒战斗，固定属性、奇穴、秘籍与零网络延迟。

构建：`cargo build --release` 产物。

方法：每种模式预热 3 次，再串行请求 30 次；计时包含本机 HTTP 往返、响应体读取和 Python JSON 解析。P95 使用 inclusive quantile。

| 模式 | 响应体特征 | 样本 | P50 | P95 | 平均 | 最小 | 最大 |
|---|---|---:|---:|---:|---:|---:|---:|
| Full | 约 3.10 MB，1648 个 timeline 事件 | 30 | 47.973 ms | 62.411 ms | 53.124 ms | 45.836 ms | 128.962 ms |
| Lite | 约 747 B，无 timeline | 30 | 16.365 ms | 17.532 ms | 12.755 ms | 6.510 ms | 17.801 ms |

一次拆分测量中，Full 的响应头等待约 70.2 ms、3.10 MB body 读取约 2.8 ms、Python JSON 解析约 30.5 ms；Lite 的对应值约为 6.9 ms、0.1 ms、0.04 ms。该单次拆分只用于解释成本构成，不作为稳定分位数。

## 6. 当前判断与下一步

已经可以确认：

- 同输入重复执行稳定，Agent 后续可以把 fingerprint 用作工具调用和评测的行为锚点；
- Lite 模式能在不改变数值结果的前提下显著减少传输和解析成本，适合作为 Agent 批量调用的默认模式；
- 现有回归体系确实能拦截 silent drift，而不是只有“测试全绿”的展示作用。

进入 Agent 工具层前仍需完成：

1. 逐处用 setter 修复当前版本的直接状态写入，并分别验证 fingerprint 变化；
2. 追溯两个绝云场景的 golden 漂移来源；
3. 只有确认新行为正确后，才在独立提交中更新 golden；
4. 清理或登记 17 个编译 warning，至少确保新增 Agent 代码不继续增加 warning。
