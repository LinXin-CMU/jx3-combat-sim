# Agent 循环基线报告恢复（2026-09-03）

## 问题

“这套循环的整体输出和伤害结构怎么样？”在真实模型会话中出现了五类叠加故障：任务被私有保存方案语义误路由；同一轮重复模拟；模型输出被截断或返回不完整 JSON；报告归一化过早裁掉伤害、时间线与增益指标；模型报告校验失败后，系统又把零散可信句与机械兜底文案拼接，最终产生“8 次空档”、无依据修改怒气阈值和标点残缺等不可靠内容。

## 修复

- 路由改为显式问题证据优先：未出现“保存、方案、仓库”等词时，私有保存方案目录不能抢占循环基线任务。
- 循环基线只调用一次高层 `analyze_timeline`；该工具同时返回模拟和时间线证据，不再先调用重复的 `simulate_scenario`。
- 单轮模型输出上限由 2048 提高到 4096 tokens，并把 JSON 解析错误转换成可执行的定向修复提示。
- 工具结果提供稳定的语义指标目录：DPS、总伤害、按占比排序的伤害来源、空档位置、冷却等待、怒气采样和 Buff 覆盖率都带原始 JSON Pointer。
- 报告归一化最多保留 12 个关键指标，不再按段落先到先得地截断。
- 循环基线增加维度完整性和严格数值校验：DPS、总伤害、主要伤害占比、节奏、怒气、覆盖率缺一不可；报告正文中的独立数字必须能回指工具证据。
- Buff 覆盖率按有效时间占比展示，与平均层数分开，覆盖率不再因堆叠超过 100%。
- 只问基线时禁止直接输出宏阈值或配装修改建议；没有 A/B 对照时，不得把“观测到触顶/等待”写成已证实损失。
- 若模型在一次有界修复后仍未通过校验，整份报告切换为确定性证据报告，不再局部拼接模型文本。阶段轨迹会保留失败码，供完整调试导出复现。

## 当前边界

确定性兜底能保证报告可读且数值可靠，但不代表供应商每次都能生成合格解释。后续性能优化应改为“服务端先建立数值骨架，模型只补充受证据约束的解释”，减少整份 JSON 重试，不应放松证据校验换取表面成功率。
