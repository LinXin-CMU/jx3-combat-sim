# 武学助手首版：技能轴转宏与回放修复

日期：2026-09-21。产品版本：`v2.0.15-20260921`。

## 交付范围

新增独立“武学助手”页面，与原 AI 分析并行。首页卡片、导航和快捷菜单均可进入；旧 AI 页面与供应商设置继续使用。首版不需要模型 Key，执行器直接调用现有 Rust 模拟链，不另算伤害公式。

使用方法：在循环编辑器排好手动技能轴及完整角色环境，进入武学助手，选择预算与宏页数，点击“读取技能轴并开始写宏”。已有宏可作为可选起点；留空则自动生成。页面显示当前最好已测宏、漏放/多放/变化、首次分歧与资源差值，支持停止、最近任务恢复、分页复制和下载结果包，不自动覆盖编辑器草稿。

实现链路：完整场景冻结 → 目标轴回放 → 初始宏 → 候选完整回放 → 真实决策诊断 → 条件、阈值与顺序修复 → 同窗口对齐 → 保留最好已测结果。候选训练样本来自真实释放前快照及多放反例；每次模拟，包括诊断回放，都计入同一预算。

主要模块：

- `backend/src/harness/`：契约、任务、HTTP/SSE、编译修复与动作对齐。
- `frontend/harness.js`、`frontend/harness.css`：独立页面逻辑和样式。
- `backend/tests/harness/`、`tools/harness-*-test.js`、`tools/harness-smoke.py`：回归与 HTTP 工作流。

完整协议见 [HTTP API](../PVE_HARNESS_HTTP_API.md)，后续循环搜索、自动配装与模型规划路线见 [设计文档](../PVE_HARNESS_DESIGN.md)。这些后续能力尚未接入首版。

## 验收与边界

- `reproduced` 仅表示本次冻结场景共同窗口内，主动动作身份、顺序、时间、档位、引导跳数及已采集资源通过验收；不代表全部气劲/CD 等价或游戏内验证。
- 共同窗口为半开区间，至少包含目标轴最后一个主动动作之后 1 帧，避免漏掉末次动作仍误报成功。缺少完整快照、跳过目标动作或宏页超限均不能通过。
- 起始宏和修复候选统一使用 `[条件]` 形式；补全方括号后才重放、去重与计页长。验证文本和可复制文本一致，补括号造成超长的宏不会被标为通过。
- 版本/心法及完整模拟输入被冻结。`scenario_hash` 标识场景；`experiment_hash` 同时包含算法、约束、预算、运行时表及可执行文件哈希。
- 每个 worker 同时一个 Harness 任务。旧宏优化、RL 训练/分析/预训练和配装搜索共用接纳锁，重任务之间互斥，避免旧配装搜索重入破坏运行状态。
- 次数、时间、轮数均有预算；取消在单次计算之间检查，正在运行的一次模拟先完成。HTTP 在进入模拟前拒绝极小受击间隔、超长时长与过大的嵌套团辅排程。
- 任务保留在 worker 内存，最近最多 8 个。刷新页面可恢复当前 worker 仍持有的任务，服务重启后不能恢复。结果包可下载并独立复跑，不是服务端检查点。
- 现有引擎只对宏执行应用 `pauses`；手动轴不应用该停手调度。输入含停手时会在结果中提示，实际差异仍按回放报告。
- DPS 与总伤害是各自完整模拟的观测值，结算尾段可能不同；不宣称同窗口收益、跨环境泛化或全局最优。
