# Agent v39：追问保真与工具执行修复

## 用户反馈与可复现原因

同一会话依次询问循环核心思路、关键技能的释放思路、哪些释放最亏。第三轮 `run-1a06fa57d09-12` 最终返回了整场怒气、GCD 与 DPS 概述。

私有回放中可核对的公开消息：

- 事件 000027：模型正文是一个 `inspect_timeline_events` 调用对象，后面带有孤立的 `</tool_call>`；原生 `tool_calls` 为空。
- 事件 000029：编排器把该动作当作报告送去修复。请求只含格式错误、证据与被拒文本，原问题及最近会话上下文丢失。
- 事件 000031：修复后的模型因此围绕整场统计写报告。

该故障发生在动作解析和报告修复阶段，并非关键词路由重新选中了“基线”任务。

另一条独立故障：v38 的 `canonical_tool_arguments` 删除事件查询中的 `buff_names`、`context_radius`、`limit`，并把删改后的参数直接交给执行器。补默认值仅掩盖了参数拒绝，未恢复模型要求的观察。

## 修复范围

1. 事件观察按完整参数执行和缓存；同参调用复用，改变 Buff、范围或分页可取得新观察。重复动作只反馈局部状态；连续无新增计数在取得新事实时重置。保留实际总预算，去掉术语命中后骤降的检索额度和按工具族数强制收束。
2. 兼容正文中独立、完整的工具调用对象及工具标签。只接受明确的 `name + arguments` 对象，仍经过开放工具列表与参数校验；报告、说明文字和代码示例保持正文处理。
3. 报告修复保留原问题、最近会话对象及当前判断。压缩会话时优先保留最近轮次，并保持 JSON 完整；工具参数错误和最近执行反馈也保留，便于下一轮修正。事件索引保留已请求的 Buff 列，模型投影截断时显式标记。
4. 报告部分保留取消自动插入基线、关键词生成解释及任意绑定本轮全部证据。最终结构失败时保留原主题模型解释，取消附加基线；完全无法提取回答时明确失败，完整工具证据仍留在调试记录中。有效独立句继续显示，错误数值与引用进入具体修复诊断。
5. 术语候选与正文共用赛季、客户端、心法、资料资格及体服分类过滤；范围信息保留在模型投影里。通用数字码/缩写可依据同一合格来源的重复用法形成中置信卡，含义仍来自正文。
6. Prompt v39 使用平实中文，先回答当前追问，随后解释具体状态、时间和原因。表达调整采用 `i-have-adhd` 的短段落、具体动作、减少修辞原则；未加入逐题答案模板。
