# Agent 分析师行为与证据交接基线（2026-09-03）

## 目标

本轮修复的目标不是让报告更容易“通过格式校验”，而是恢复战斗分析 Agent 应有的工作方式：先读懂当前循环的真实输出结构，再解释执行节奏和可疑信号；只有需要证明损失、收益、最优性或具体改法时，才进入同场景 A/B。语言模型负责分析，模拟器负责事实，校验器负责阻止无证据结论，但不能把一份基本正确的专业分析整体吞掉。

## 已定位的退化原因

1. 路由置信度存在 80–120 分的空档。“这套循环做得好的地方和最主要的问题是什么？”虽然最符合 `current_rotation_baseline`，仍会掉入通用分析路径。
2. 模型证据投影不是幂等的。第一次投影已把技能列表整理成伤害排行，后续交接再次投影时会因为原始 `skills` 已移除而把排行覆盖为空数组，模型因此无法看到真正的主伤害技能。
3. 发布校验把“表达完整度”与“证据安全”混为一谈。标题关键词、发现数量或维度覆盖稍有缺失，就可能用模板遥测整体替换模型报告。
4. 普通基线问题也强制检索攻略，容易让模型绕过当前模拟数据，围绕一段知识库原文过度发挥。
5. 超时、轮次预算和过大的工具批次会直接进入模板降级，已经形成的有效模型报告没有被优先恢复。

## v26 行为设计

- 路由采用语义候选与领域计划的置信度决策，消除阈值空档；同类自然语言能够稳定进入循环基线 Playbook。
- 模型侧证据保留按伤害排序的前 12 项技能、事件次数和精确证据路径；重复交接保持幂等，完整原始 Evidence 仍由服务端保存和校验。
- 当前版本攻略改为按问题需要动态启用。纯基线先看模拟器；用户明确要求攻略、白皮书、机制或当前版本依据时，再把知识检索提升为必需工具。
- 数值来源、版本越界、伪造证据等仍是硬阻断；标题风格、发现数量和非关键维度缺失改为可修复建议。一次修复后仍有表达缺口时，保留已验证分析并明确边界，不再整段替换。
- Prompt v26 要求模型区分观察、机制解释和可检验假设；正确区分技能变体、怒气触顶采样与实际资源损失、Buff 覆盖率与平均层数，以及“冷却等待”和“技能已就绪却未施放”。
- 单次基线通常覆盖主伤害承载、执行层优点和最值得继续验证的风险，但这些是弹性目标，不是机械清单。
- 超时或轮次预算耗尽时优先恢复最近一份可验证模型报告；工具批次过大时给模型一次基于现有证据收束报告的机会。

## 证据边界

- 单次当前循环基线能够描述结构和风险信号，不能证明某个修改一定提升 DPS；涉及收益、损失和最优性仍需冻结环境后的 A/B。
- 怒气触顶采样不等于已经测得怒气浪费；Buff 覆盖率与平均层数必须分别计算和表达。
- 外部模型仍有随机性和供应商延迟，工程层只能保证有效证据不被交接丢失、正确报告不被软规则整段吞掉。
- 当前仅为本地 3005 原型验收，不构成公网部署完成。
