# 确定循环宏压缩：2026-10-02 执行记录

本轮实现了完整观察窗口查询、区域联合重写、公开宏语料流程，以及可选的候选学习排序和策略调度。所有更新最佳宏的入口仍要求原生执行器独立完成全程认证。没有得到比既有 397 字更短的长例结果，也没有证明学习或区域搜索提速，因此两个学习开关和区域搜索保持默认关闭。

第一阶段的目标、条件目录和无字符限制未被这些压缩改动替换。第二阶段沿用原合同，不因压缩再次放宽时间。未新增步骤计数、其他解释器或跨任务宏答案复用。

旧的快速窗口启发式保留为提案来源。新增完整窗口搜索不再把旧施放点当作唯一正例：旧选择只识别受影响事件，新见证可以在该事件允许窗口的其他观测上出现。首个合法见证后，旧路径中同事件的尾部快照不再成为强制标签；此前误放与终点额外动作仍被检查。未观察到的调度时刻最终由真实回放补充。

扩展窗口只对拥有额外合法见证的事件展开，避免重复遍历单点窗口。这个筛选只安排一个提案生成器，不是对合法宏空间的否决。其他优先级、规则族和区域生成器继续保留。

## 固定长例

版本/心法为暗影千机/分山劲，325 次主动施放，终点 299.4575001 秒。验收为 `skills_and_time`，绝对时间容差固定 62.5ms；场景摘要为 `b509513f86a476decedbd174baa2c0c92dfe1976b058aa94185a925b3394e57a`。对照宏 B 未输入这些搜索或学习。

| 运行 | 起点→认证结果 | 首次达到结果 | 整轮时间 | 试算 / 严格改进 |
| --- | --- | ---: | ---: | ---: |
| 修改前本轮重测 | 3110→397 字 | 202.3s | 215.9s | 381 / 67 |
| 恢复原快速顺序后 | 3110→397 字 | 206.0s | 220.3s | 381 / 67 |
| 另一个认证起点 | 518→397 字 | 44.7s | 59.1s | 99 / 8 |
| 397 起点最终快速路径 | 397→397 字 | 起点已认证 | 14.9s | 24 / 0 |

以上最佳宏均 325/325 顺序与时间通过，最大误差 50.0ms，完整终点回放完成且未截断。它们没有满足完整内部状态一致的结论。计时不含第一阶段提取；离线观察上限为 300/150/60 秒，产品没有任务总时限。长例的主要对照顺序运行；单轮差异不能宣布提速。

最终的单点窗口去重调整在 397 停滞起点单独复核，保持相同 24 次试算和结果。3110/518 实测是该调整前的最后完整长跑，不能把这项调整后的完整长跑时间编造出来。各运行保存自己的模块摘要。

### 失败路线及默认选择

直接让完整窗口搜索替代快速搜索时，3110 字起点两轮停在 424 字，分别为 219.5s 和 211.4s。构造合法候选的能力扩展并不保证贪心搜索路线更好。因此改为保留原先快速顺序，在该邻域停滞后才扩展。这些失败记录保留，不从结果统计中删除。

早期区域接入还误触发旧修补队列，导致 301 次修补试算、77.1s、没有缩短；已改为只有该区域实际产出新候选时才触发相应修补。修复后的初始小范围版本为 23.1s，仍无长度改善。最终区域入口允许轮转更多区域及等成本桥接，属于可选探索，不能沿用这项小范围时间宣称最终入口速度。

区域 `(3,4)` 的独立检查在两个槽位、三条件、16 原子、500ms 时间片下得到两份不同正文的 397 字宏，均完整通过 325/325。其实际施放指纹与原宏相同，验证了联合重写能力，未证明时钟/状态路径多样性收益。血怒区域扩大为六条件、24 原子、500ms 后仍是 UNKNOWN。有限 UNSAT、UNKNOWN 和原生失败分别记录，均不被转换为全语言无解。

### 开销拆分

3110 最后完整运行记录：候选构造/求解约 84.6s，样本构造 12.9s，原生验证往返约 82.2s，额外完整反例观测往返 34.2s。剩余为调度、排序、存档等开销；这些计时与策略整体时间存在嵌套，不能再次相加。

75 个完整通过候选的认证阶段，平均原生准备 0.07ms、带探针回放 326.0ms、投影与本地归档 232.5ms、Python 解码 20.0ms，第二遍认证往返 690.8ms；包括第一次精简筛查的平均验证时间为 841.5ms。306 个失败候选首次确定分歧后结束，平均往返 62.2ms。

`replay_with_probe`包含条件观测成本，不是纯战斗模拟核心时间；`projection_and_archive`也不是网络耗时。记录的约 203.6MB 是本地 Rust→Python 管道中部分响应的累计字节，未包括所有反馈/首遍筛查，不是完整流量统计，更不是 VPS 对浏览器的流量。原始包、模型与哈希不放入公开任务报告。

同一个代码快照、场景和原生程序，三种模式顺序运行：

| 模式 | 起点→结果 | 压缩耗时 | 原生试算 | 训练标签 |

| 基础 | 317→178 字 | 2.620s | 13 | 0 |
| 区域 | 317→178 字 | 10.420s | 13 | 0 |
| 区域＋排序＋调度 | 317→178 字 | 10.169s | 15 | 15 |

每份最佳宏又独立完整回放：23/23，零时间误差、内部状态一致、终点完整，合同为 `skills_and_state`、1e-7 秒容差。没有净收益证据，0.25 秒差异不足以证明学习提速。15 个训练标签都是正例，没有证明负例校准、泛化或跨场景模型有效。

另做原子目录反转检查：424 列真值按置换对应，观测语义与学习特征保持对应；得到的 178 字宏独立通过。此前两轮代码摘要不同，因此不将其 4.93/10.20 秒用于排列或学习速度比较。

排序始终保留候选并保留探索。静态筛选、UNKNOWN、截断、取消和未认证反馈不作为失败训练标签；只有完整通过或确定的原生首次分歧提供标签。固定 325 参考家族保留为测试组，学习不更新。模型按合同、原生版本和来源分组绑定，不自动跨合同导入。

## 语料与实际 worker

完整语料说明见 [公开宏语料记录](2026-10-02-exact-macro-corpus.md)。40 宏块为 review 26、明确测试组 8、隔离 6；train/validation 均为零。当前宏库流程没有训练模型。公开宏不能在生产中作为目标检索出的现成答案。

实际 worker 使用原始短 fixture 自动提取后压缩：总 2.11s，11 次试算，185 字、23/23 完整通过。该起点与 317 字压缩对照不同，不能将时间直接比较。实际 stdin 暂停 300.66ms，期间没有进度事件，有效计时扣除暂停；停止约 41ms，两个 oracle 均退出。无 HTTP 服务或真实 userdata 写入。

## 边界与后续

本轮完成最小纵向工程及必要评测，未证明更短全局最优解，也未证明全部宏无解。当前区域求解仍为单页样本投影；引导按原生执行验证，多页或缺失切页信息的语料明确报告构造限制。未来扩大语料、训练离线模型、跨场景验证与高效多页合成尚待实施；需要真实净收益后才调整默认开关。

Rust 核心、数据与前端交互未因本轮算法改动而重写，因此未重复无关 Rust 全量测试。源码发布和在线服务切换分别记录；本轮不重启在线服务，不恢复用户已明确不保留的任务。
