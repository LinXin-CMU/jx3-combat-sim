# Agent 模型主导架构 v38 基线（2026-09-05）

## 为什么重构

上一版虽然能稳定完成若干固定题，但把任务分类、分析维度、结论措辞和部分玩法语义写进了 Rust 与 Prompt。它能提高题集命中率，却会让模型在题外问题上复述模板、重复读取工具，或在没有命中预设路径时失去判断能力。这属于对测试问题的有害特化。

本轮目标是保留苍云模拟器必需的领域事实，把“用户问什么、应该怎么查、最后怎么判断”还给模型。

## 已删除的有害特化

- 删除关键词/相似度任务路由，所有问题统一进入 `model_led_diagnosis`。
- 删除固定任务 Playbook、固定维度清单与逐题 forbidden inference。
- 删除代码内手写玩法结论表；知识正文不再被 Rust 转写成预设结论。
- 删除白刀专用汇总、报告 fallback 和事件 selector。模型不能直接调用“查白刀”；它必须先从攻略理解术语，再把含义转换为通用技能、Buff、资源和时间轴查询。
- 删除工具说明中残留的白刀能力承诺。

仍保留的领域能力不是答案特化：版本/客户端/心法边界、宏解析规则、技能资源交易、Buff 覆盖率与平均层数、伤害链和可复现模拟。这些是 Game × AI 系统用于约束事实的领域环境。

## 当前架构

1. 服务端只解析客户端、赛季、心法和页面上下文，不给问题贴任务标签。
2. 模型维护动态诊断状态：用户目标、当前判断、已知事实、证据能力、开放假设和候选实验。
3. 本地知识库从攻略正文自动抽取版本化术语卡，保存词面、别名、词义依据、赛季、置信度和来源指针。检索正文仍是正式引用 Evidence。
4. 模型自由选择场景、知识、模拟、时间轴、事件、保存方案、配装和 A/B 工具。
5. 编排器按证据能力和信息增益管理上下文：高置信术语和当前版本正文已经取得时，合并同义检索；未命中或宽泛研究仍可继续扩展。
6. 同一事件选择范围只计算一次。Buff 列、窗口半径和展示条数属于投影参数，不再制造新的确定性工具调用。
7. 草稿若自己声明还缺一层会实质影响答案的证据，工具循环可重新开放一次，由模型决定补证或保留边界。
8. 发布校验只检查数值来源、版本、引用、宏位置与“实测/推断”归属，不代替模型决定玩法观点。

## 上下文与兼容性

- 工具即时输出预算为 8 KiB，长期 Evidence handoff 为 12 KiB。
- 术语卡给模型传递简明词义和来源指针，不再在每个 Evidence 中重复整篇来源正文。
- Evidence handoff 按能力均衡保留场景、资料、模拟、时间轴、事件、保存方案与配装证据，避免知识片段挤掉战斗事实。
- 精确事件号、时间、技能、宏行和效果优先于大段聚合载荷。
- `inspect_timeline_events` 只要求 selector；安全分页和展示参数可由服务端补默认值。范围上限仍在服务端校验。
- 既有会话保持 append-only；公开 API 继续返回脱敏投影，私有 replay 保存可复现原始记录。

## 真实模型结果与诚实边界

真实用例 D05 要求先解释当前赛季“白刀”，再结合冻结宏判断实际位置。该用例用于检查术语理解与通用事件 API 的桥接，不作为完整泛化证明。

| 轮次 | 结果 | 观察 |
| --- | --- | --- |
| v37-r2 | 超时，180 秒 | 6 次知识检索，未转向事件定位。 |
| v38-r3 | 部分通过，63 秒 | 能解释术语，但未读取事件便声称具体位置。 |
| v38-r4 | 部分通过，116 秒 | 检索降到 2 次、工具降到 4 次，仍停留在宏语义推断。 |
| v38-r5 | 部分通过，149 秒 | 成功调用通用绝刀事件，但重复改变投影参数，10 回合后降级。 |
| v38-r6 | 部分通过，144 秒 | 模型主动把攻略语义转换成多个通用技能查询，但缺省参数被严格校验拒绝；此接口问题随后修复。 |
| v38-r7 | 超时，180 秒 | 缺省参数修复后的供应商调用未收束，没有形成最终报告。 |

因此本轮证明了“无专用白刀入口时，模型能够提出通用技能/Buff 查询”，也证明了自动回归边界稳定；尚未证明 DeepSeek 在开放任务上能稳定、快速地把查询结果组织成可用答案。供应商时延、空响应和自主收束仍是产品风险。

## 下一验收节点

停止继续调整单一白刀题。下一轮从 12 题中抽取至少 5 类进行盲测：开放循环体检、知识库陌生黑话、具体位置定位、保存方案比较、配装比较、真正缺信息时追问。每题人工检查：

1. 是否先回答用户真正的问题；
2. 术语是否来自正确版本资料；
3. 是否选择了能改变判断的工具；
4. 是否把聚合信号落实到具体事件或明确边界；
5. 是否有不必要的重复调用；
6. 总时延、模型回合、输入/输出 token；
7. 回答是否自然、专业、可执行。

跨题可用率达到 80%，且没有版本越界、虚构实测和错误宏位置，才把该版本标记为可用原型。
