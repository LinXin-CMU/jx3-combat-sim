## 凭据与费用边界

API key 只保存在用户级环境变量 `JX3_DEEPSEEK_API_KEY`。仓库配置仅保存环境变量名，安全启动脚本只把 key 注入子进程；浏览器、会话、trace、日志和 Git 都不保存 key。

开发评测硬上限为 USD 0.70。成本按官方 cache-miss 输入 USD 0.435/M token、输出 USD 0.87/M token保守计算。当前可计量调用合计约 USD 0.161840；另有少量失败请求没有返回 usage，因此不把这个数字表述为账单精确值。

## 发现与修复

- DeepSeek 的工具轮次与 JSON mode 组合可能返回空白内容：有工具时不再发送 `response_format`，最终无工具修复轮次才启用 JSON object。
- 复杂工具 transcript 上直接做报告修复会触发上游请求错误：修复改为独立、无工具、只包含被拒可见 JSON 的新请求。
- 模型经常把 metric 的 evidence id 放在 metric 内，却漏掉 finding 外层引用：服务端只对“本轮已存在的同一 evidence id”做确定性补链，然后继续执行数值、单位与 JSON Pointer 校验；未知或数值不匹配仍拒绝。
- 真实失败主要集中在 `missing_metric_source` 与 `metric_value_mismatch`。安全回退为 `evidence_insufficient`，未经验证的数字不会进入报告。

## 真实多轮会话

发现原实现只保存 `parent_run_id`，并未把上一轮可见结论送入下一轮模型上下文。现已改为从 append-only 会话中重建最近两轮的有界可见报告；不包含 provider transcript、隐藏推理或凭据，历史数字也不能充当本轮证据。

真实续接 run `run-1a03bfb043b-0` 在既有 session `session-1a03be31db5-0` 上完成：模型识别上一轮使用英文分析确定性基线，按当前中文问题重新调用 `get_current_scenario` 与 `simulate_scenario`，生成一份当前轮 evidence 支撑的报告。该轮 10,409 tokens、约 USD 0.005298、20,983 ms。

## 当前结论

Phase 2 的工程闭环和真实部署链路已成立，但真实模型固定题集尚未达到可称为高可靠产品的门槛。作品集应展示“证据约束、失败降级、成本治理、跨供应商兼容和诚实评测”，而不是宣称模型能稳定回答所有策划问题。
