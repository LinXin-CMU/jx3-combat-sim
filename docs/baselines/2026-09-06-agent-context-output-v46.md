# v46 上下文、输出与时间预算

## 问题

用户反馈 run-1a076699ed2-1：8192 completion tokens 后没有正文；重试同样达到输出上限，报告以 length 截断；结构修复时剩余约 21.6 秒，最终超时。此轮没有完成候选宏对比。

## 改动

- 历史上下文从最近 2 轮改为 4 轮；字段上限 256 → 512 字符，会话预算 16 → 32 KiB，通常请求中的历史压缩阈值扩大到 8000 字符。
- 请求体工程上限 72 → 128 KiB；单工具摘要 8 → 12 KiB；证据交接摘要 12 → 24 KiB。继续去重与按需展开，完整证据仍在后端。
- 默认输出 8192 → 16384 tokens，输出不足时有界重试提高至最多 32768。这里是应用额度，不是供应商能力声明。
- Chat length 且无正文单独记录 provider_output_limit；计费用量保留。
- 单请求时间根据输出额度至少预留 180/240 秒，但服从总截止时间；有界报告重试可在无需新证据时延展总时间，默认绝对上限仍 600 秒，显式自定义截止时间不扩张。
- Prompt v46 补充先交付完整代码，再写验证结果与必要解释。
- 按用户要求，没有新增截断 JSON 抢救、字符串拼接或半份宏发布逻辑。
