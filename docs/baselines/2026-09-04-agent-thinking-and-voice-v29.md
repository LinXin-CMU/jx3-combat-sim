# Agent 推理模式与分析师表达 v29 基线

日期：2026-09-04
状态：本地实现、回归与 3005 真实模型验证完成；领域判断质量仍需继续评测。

## 问题

反馈 run `run-1a06a27668e-10` 中，DeepSeek V4 Flash 实际生成了多条玩法判断，但最终报告使用 `claim`、`name` 等兼容字段，连续两次未通过严格结构解析。发布层随后用确定性指标模板覆盖了模型正文，用户只能看到 DPS、伤害占比和覆盖率。

代码审计同时发现，DeepSeek Chat 适配器显式发送 `thinking.type=disabled`。这避开了思考模式工具续接所需的 `reasoning_content` 协议，却也让 Pro 与 Flash 都以非思考模式执行复杂战斗诊断。

## 改动

- Prompt 升级为 `agent-system/v29`，以“判断先行”为核心：模型先回答真正的优点、主问题与因果链，再决定关键取证动作。
- DeepSeek V4 Pro 启用 high thinking；V4 Flash 启用 low thinking。
- 工具回合在内存中原样续接供应商 `reasoning_content`；该字段不进入公开 trace、调试导出、会话文件或私有 replay。
- 单轮输出预算由 4096 提升到 8192；供应商请求超时由 60 秒提升到 120 秒，总 run 仍受 180 秒上限控制。
- 报告解析兼容 `claim/name`、中文单位、字符串 recommendations 等常见模型 JSON 方言。
- 严格结构仍失败时，发布层保留模型的自然语言判断，再由不可变 Evidence 重建独立指标卡；格式错误不再抹除回答。
- 将模型只返回 action plan、没有实际工具调用的情况送回执行循环，而不是误判为最终报告。
- 知识检索参数中的字符串 `"null"` 在服务端归一化为空值，避免无意义的类别错误。
- 上下文压缩后的续接指令改为继续当前结论、复用已有证据，减少重新规划。

## 真实模型观察

同一 313 步手动循环、同一问题“这套循环做得好的地方和最主要的问题是什么？”：

- V28 非思考模式：7 个模型回合、10 次工具调用、62,039 tokens、36.3 秒；最终 JSON 结构失败，玩法判断被统计模板替换。
- V29 Flash low thinking：8 个模型回合、12 次工具调用、94,374 tokens、134.1 秒；模型直接给出了循环阶段设计、主要问题、机制解释与对照建议，正文在单项证据指针失败后仍被保留。

这证明表达通道已从“验证通过后才允许说”改为“模型判断先发布、证据状态同时展示”。当前剩余问题转为推理效率与领域正确率：本轮重复调用了确定性时间轴，且关于援戈尾段的判断尚未执行同场景 A/B，不能作为已验证玩法结论。
