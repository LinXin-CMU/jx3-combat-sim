# 宏固化：单次提取与独立验证

## 问题及修复

旧固化先把宏块改成技能块，再逐次模拟、修正一个释放偏移。失败项没有实际释放时间时，会把时间当成 0，从而把目标的绝对时间误写为相对偏移；已经写过的偏移又不复查。最终没有完整验收，也可能返回成功。

另一个错位来源是自动触发伤害的图标也具有 `sim-seq-item` 类名。它们不能参与操作序列、固化索引和对照请求。新逻辑排除自动图标和自动换行；主动事件使用后端 `sequence_index` 映射，不按成功次数猜测位置。对照中的失败项也不再冒充成功施放。

## 新流程

1. 用完整当前场景模拟原宏一次，在每个宏块中记录成功动作以及施放之前的相对等待检查点、强制施放标记。
2. 在内存中准备普通技能序列，把等待记录放入每个技能块的 `solidified_cast`；不修改界面或存档。
3. 独立模拟候选一次。比较全部主动技能身份、时间、引导跳数、施放前后状态、怒气，以及终点和总伤害。
4. 全部通过才一次性应用。请求失败、配置变动、切页、回放分歧均保留原宏块。

已有当前完整场景的有效原宏轨迹时，直接读取其中的等待记录，只请求一次独立验证；结果过期或缺少记录时，才先提取一次，最多两次请求。不是“每个异常点跑一次”，也没有把验证省略成直接复用目标结果。

等待检查点从宏调用开始计相对时间，不是绝对施放时间。实际推进仍调用 `process_buff_ticks`，实际施放复用宏、RL 已使用的 `execute_cast`；不会重新解释宏条件。保留中间检查点是必要的：当前铁骨盾压期望冷却的推进与中间扫描有关，只保留成功施放的时间并批量推进，不能保证相同状态。这次没有修改概率公式或全局伤害计算。

固化记录随技能块保存、导入、导出、复制和分页对照；改动该项的释放偏移或引导跳数会取消该项的记录，恢复普通编辑行为。修改完整场景后不保证仍与原宏相同。原来已写入的错误偏移不自动改写，需要从保留的原宏重新固化。

## 验证结果

正式服暗影千机 / 铁骨衣的本地冻结场景，300 秒，原宏实际成功施放 334 次。场景及完整轨迹仅保留在本地测试留档目录，不写入用户存档。

| 项目 | 旧固化 | 新固化 |
| --- | --- | --- |
| 成功施放 | 324 / 334 | 334 / 334 |
| 校准次数 | 17 轮校准 | 无逐点校准 |
| 固化请求 | 随异常点增加 | 有效轨迹 1 次；否则提取 + 验证 2 次 |
| 最大施放时间误差 | 存在累积偏移 | 0 秒 |
| 总伤害与终点 | 未通过完整验证 | 与原宏一致 |

本机 HTTP 测量：原宏提取约 605 ms，独立回放约 553 ms，总计约 1.16 秒，包含完整结果的生成和通信；不是对所有配置或线上延迟的承诺。状态比较将无序的技能冷却集合排序，不把 HashMap 顺序当作战斗差异。时间验收容差为 1e-6 秒，场景实测误差为 0。

浏览器已验证有效轨迹只发送 1 次验证、无有效轨迹发送 2 次，以及 334 个宏块全部固化、导出再导入后回放一致、故意改变验证结果时保持原序列。单元测试覆盖两个正式服心法、网络延迟、等待、停手、错误动作和无效等待。

Rust 全量测试：611 通过、1 项原有忽略；后续保存路径补齐通过 5 项保存测试，固化 2 项测试通过。前端语法及固化纯函数检查通过，脚本 setter 静态检查通过。

两正式服版本的 8 个回归场景：确定性、Lite/Full、数值与指纹一致。Golden 检查仍因数据/脚本目录哈希与旧档不同而失败，未改写 Golden；不能把整个回归命令描述为通过。

## 合成入口传递修复（v2.1.0-20260930.13）

固化本身和普通模拟已携带等待记录，但合成入口通过 Harness 工作区重新构造请求时遗漏 `solidified_casts`，工作区转换为技能块时也遗漏 `solidified_cast`。这使有效的固化目标被当成普通立即施放序列，错误提示目标存在未成功释放的技能。

现在工作区读取、应用和技能块转换均保留等待记录。生成宏的运行请求显式清空固化记录，避免使用参考序列的等待记录影响候选宏验收。完整场景数据和结果仅保留在本地测试留档中，未改写用户存档。

当前暗影千机 / 铁骨衣保存场景有 351 个主动技能块、351 份固化记录。对同一完整场景去除等待记录时，目标准备返回 `invalid_target`，出现 5 个未释放项；首次为第 65 项怒气不足（需要 10，实际 5）。保留记录后，目标准备及探测返回 `ok`，技能和时间验收前缀为 351/351，没有首次分歧；目标准备及探测约 0.746 秒。此结果验证目标准备，不代表已求解出完整宏。

真实浏览器验证工作区捕获请求保留 351 份记录、技能块转换保留 351 份记录，独立回放成功 351 次、未释放项 0、与当前循环回放无分歧。固化纯函数检查、相关前端语法检查和 22 项 Harness / 合成界面测试通过。仅前端修复及资源缓存版本更新，无需重启后端。

## 边界

固化接受的前提是独立回放通过。未成功释放的宏块保留，验证失败不会保存部分结果。该功能固化一份已执行的操作序列，不证明任意宏可表达性，也不代替宏合成的真实回放验收。
