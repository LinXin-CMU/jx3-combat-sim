## 战斗回归的已知差异

`diff_baseline.py --version all` 的整体退出码仍为失败：两正式版本共 8 个 Golden 场景仅报告 `data_sha256` 元数据漂移。三次重复的确定性、Lite / Full 一致性，以及 Golden 的 DPS、总伤害、时长和事件指纹均保持一致。

该漂移在本次 Harness 开发前的工作区配表变动中已存在。本次没有修改伤害计算链，也没有自动更新 Golden；不能将这个命令描述为全部通过。之后整理既有配表变更时应单独审核元数据基线。

## 真实模型验证

最终结果由 `tools/harness-run-smoke.py` 的隔离 worker 实测报告汇总。测试包括故意阻塞的宏修复、输出循环、锁位配装及配装与循环联合实验；每项都检查所选候选、完整回放和应用／撤销事务。小题集只证明这些场景，不推算生产成功率。

最终一轮使用 `deepseek-v4-flash`，**4 / 4 完成并交付 verified 候选**：

联合题保留原奇穴和秘籍、开放可用技能、仅允许更换帽子，检查最终候选确实继承配装实验并完成不同延迟的独立回放。该题配置 24 次调用、192 次模拟、240 秒和 256k Token；单功能题为 16 次调用、96 次模拟、240 秒和 96k Token；单轮输出均为 8192。耗时包含本机服务和模型等待，不作为标准化性能比较。

**这不是全部开发尝试的成功率。** 此前联合题曾在 192k 预算下用尽额度，一次触发 4096 Token 单轮输出截断；另一次已完成联合验证，但预算不足以写最终报告。相关失败促成了上述记忆、信息分层、预算提示与报告投影修复。复杂任务仍可能只留下部分证据；可调整高级预算，不能承诺任意目标都在默认预算内完成。

## 实际发现并修复的失败

1. 压缩后丢失刚刚读过的资料，模型反复重新规划：保留最近完整调用与返回，保存观察缓存，增加旧证据分页。
2. 摘要混入完整模拟请求和大量宏占位动作，压缩后仍过大：只投影验证指标与身份，账本设置独立体积上限。
3. 最终说明里的数字触发反复改写，耗尽预算却无法交付已经成功的候选：报告投影移除未获数值支持的句子并明确披露，候选资格仍由模拟证据决定。
4. 留出环境与实际应用环境混用：分别保存应用指纹与验证结果，编辑器核对应用环境的指纹。
5. 浏览器序列化默认值、装备展示字段引发假“场景已变更”：按类型归一化比较，真实环境差异仍拒绝覆盖。
6. 大整数指纹被 JavaScript 数值截断：按原始 JSON 字符串保留并比较。
7. 联合任务读取过多完整定义，Token 消耗超过收尾余量：工具默认返回紧凑目录与摘要，按需分层读取详情；依据近期实际输入规模预测验证与交付所需余量。
8. 装备标签集合的无序序列化使同一数据跨进程的身份不同，误拒绝任务恢复：仅对身份投影中的集合排序，数值或标签内容改变仍使身份失效。
9. 复杂任务的模型回复达到单轮输出上限，之前被误报为连接中断：分开提示输出截断与网络错误，提供可调输出额度，并在系统指令中实时提醒预算收尾。

## 数据与交付边界

测试仅写入临时隔离目录。原 `backend/userdata` 的 **36,342 个文件**在验收前后清单内容哈希一致。未迁移、删除或批量改写既有会话。测试结束清理自建进程和临时用户目录。

配装搜索得到的是候选目录及预算内的结果，不证明全局最优；自动搜索保留现有强化配置，完整自拟配装可以走同一校验入口。装备价格、赛季获取日期或实际可获得性缺少可靠数据时保持未知。有限延迟验证不能替代游戏内测试。编辑器无法无损表达的特殊宏分页可导出，但不能直接写入。

发布包不包含 Key、运营配置、用户数据、私有知识库、原始资料或获取过程。公开部署另行完成 HTTPS、鉴权与入口限流。复跑命令与 API 见 [HARNESS_V2.md](../HARNESS_V2.md)，三分钟案例见 [HARNESS_CASE.md](../portfolio/HARNESS_CASE.md)。
