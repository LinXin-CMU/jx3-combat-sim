# v44 宏语义与澄清续接

## 本次反馈核查

原始目标是完全复刻手动轴的血怒位置。第二轮提出用狂绝作为状态锚点；用户只补充“已分体态擎刀页”，第三轮却删除状态锚点，退回仅检查血怒Buff断档，并声称放在斩刀下面即可。

- 实际第三轮 run_input 的 session_context 中，上一轮 analysis_text 被截到256字，恰好停在 `/cast [b…`，没有完整候选条件。
- 宏引擎 Phase1 按状态扫描条件，Phase2 按源行顺序选首个当前可释放技能，成功施放后下一轮重新扫描。源行顺序不构成固定连招队列，分体态也不自动保证斩刀后释放。
- 第二轮逗号连接条件在当前解析器中变成一个Buff名称；合法逻辑与写 `&`。`rage` 明确存在于解析器和求值器；反馈中的“官方支持不稳定”没有相应证据。本次文档只陈述本项目实现，与游戏客户端能力区分。
- 当前输入为手动轴时，过去的宏运行元数据没有自然进入场景宏摘要；模型做宏设计仍需要这些规则。

## 变更

- `backend/prompts/macro_runtime_reference.md` 提炼实际语法、右结合运算、缺失Buff的时间判断、充能/怒气/层数、last_skill实际成功释放语义、分体态选页及重复扫描行为；由 mechanics_context 常驻提供，手动轴也可使用。
- 待澄清历史保留1200字分析概要，以及完整的短候选代码块（最多3块，每块800字）；请求压缩时小代码块整体保留，标明历史未验证候选。原目标单独记录 continuation_goal。
- Prompt v44 说明澄清更新约束、候选继续核对；精确复刻同时检查目标释放和非目标位置的误触发。
- 未改宏解析器、执行器或战斗公式；未自动覆写用户宏。
