# 2026-10-04：AI 分析任务验收与最终宏核验

当前源码版本：`v2.1.0-20261004.5`，Prompt `agent-system/v53`。

工程回归、release 构建、隔离浏览器验证及 10 次隔离真实模型任务已完成；10 次结果均已完成独立 Agent 语义审读。本记录不表示已经更新日常运行服务或完成部署。

## 问题与范围

AI 分析已有模型工具循环、冻结场景、证据引用、数值校验和可回放记录。但报告格式及引用校验通过，只能证明报告满足这些数据约束，不能证明用户要求的对照实验、完整宏交付等事项已经完成。模型交付宏之后修改一行、条件、顺序或分页，也不能继续使用旧候选的结果证明最终文本已实测。

本次增加独立的客观验收结果，修正报告输出契约，并让界面和导出报告显示验证依据。模型继续自主选择工具与组织正文。验收不足不会删改回答、自动追加模型调用、强制模拟或改变原运行状态；没有新增停止策略、累计 token 上限或成本控制。

审计和改动对象是 `backend/src/agent/*` 的 AI 分析。`backend/src/harness/run_*` 的武学助手运行时独立存在，其检查点续跑、工作区应用/撤销不能作为 AI 分析已实现的能力。

## 三层状态

1. **运行状态**：既有 `AgentRunStatus` 表示本轮已完成、部分验证、失败、等待输入等生命周期状态。
2. **报告校验**：既有报告解析、数值、单位、来源和引用校验继续执行。定性论证的充分性与因果正确性不由这些检查保证。
3. **任务验收**：新增 `task_completion`，只核对显式列出的客观条件及最终宏。`semantic_review_required` 始终为 `true`。

| 任务验收状态 | 含义 |
| --- | --- |
| `checks_passed` | 已列出的客观检查通过；不表示语义已审定、方案有提升或达到最优。 |
| `checks_incomplete` | 显式条件或最终宏的运行依据尚未补齐；完整回答和候选保留。 |
| `needs_review` | 没有客观执行验收项，例如纯定性设计讨论；不因此要求模拟。 |

因此，同一轮可以同时具有 `status=completed` 与 `task_completion.status=checks_incomplete`：运行已经结束，客观交付条件尚未全部满足。这是两份不同的状态契约。

## 显式验收条件

`POST /api/agent/runs` 请求新增可选字段，以下仅展示该增量字段：

```json
{
  "acceptance": {
    "min_comparison_candidates": 2,
    "require_macro_artifact": true,
    "require_simulation": true
  }
}
```

- `min_comparison_candidates` 为 `0..=8`，默认 `0`。按真实候选的不同 `scenario_hash` 计数；不计基线、重复候选、无变化记录及没有实际施放的记录。相同战斗结果可以是一次有效实验，不把“结果没有变化”混同于“没有测试”。
- `require_macro_artifact` 默认 `false`。要求最终报告交付可解析的完整宏；每份最终宏是否与实测一致仍单独核对。
- `require_simulation` 默认 `false`。要求当前冻结场景存在有效指纹、时长及实际主动施放的模拟证据；读取场景本身不能满足此条件。
- 不接受未知字段、负数、错误类型或超过范围的候选数。HTTP 层与编排器入口均在模型调用前检查。
- 这些条件由调用方对本轮显式指定，不从问题关键词暗中推断，也不自动继承为下一轮的强制要求。模型上下文会说明本轮条件；最终判定使用实际工具证据。

无显式条件时仍会检查最终宏。纯定性回答或非宏文本不会被附加“必须模拟”的隐含要求。

## 证据和最终文本核验

实现位于 [`completion.rs`](../../backend/src/agent/completion.rs)。评估函数只读取冻结场景、最终报告与可信工具注册表中的证据，不调用模型或模拟器，不改变工具预算。

证据先检查 `agent-evidence/v1`、工具来源、当前场景标识、登记的 `evidence_id` 与证据内容身份散列。失败工具包装、错场景、被修改或截断的记录不能满足条件。证据散列用于一致性校验；来源信任仍来自服务端工具注册表，不把散列当成任意外部材料的真实性证明。

真实执行证据支持三条路径：

- `compare_scenarios`：基线必须对应当前冻结场景；候选必须包含变化、有效指纹与实际施放。根据完整 `changes` 从基线重建候选，再检查候选场景散列，避免只凭工具名称、标签或模型描述算作对照。被序列化省略的默认参数使用基线的实际类型值补回后核对。
- `simulate_scenario`：结果必须包含有效指纹、时长、实际主动技能记录。当前场景已经使用与最终交付物相同的完整宏时，可以复用该证据。
- `analyze_timeline`：使用该工具自身的指纹、时长、主动施放计数及技能记录核验，不强迫为了验收再调用一次 `simulate_scenario`。

最终宏匹配仅归一 CRLF 与全文首尾空白；不忽略条件、顺序、分页、注释或内部空白。宏语法由本地解析器检查，不相信模型写入的 `syntax`。保存到完成结果的 `content_sha256` 是最终原文的 SHA-256，匹配和原文指纹是两个不同用途。

宏匹配还必须证明执行过宏：场景需要包含宏执行入口，并有成功的宏行施放记录。对于没有宏行明细的模拟摘要或历史比较记录，仅纯宏序列中的实际主动施放可以代替该明细。手动序列附带一段从未运行的 `macro_text`，只能证明手动模拟发生，不能证明该宏已测。

| 最终交付物状态 | 含义 |
| --- | --- |
| `simulation_matched` | 完整文本与已执行宏一致，并绑定对应证据。 |
| `not_tested` | 未找到与最终完整文本一致的有效运行证据。 |
| `invalid_syntax` | 本地宏解析未通过；原文仍保留。 |
| `not_executable` | 不属于本地宏执行契约，例如普通设计说明或其他语言代码，需要人工审阅。 |

宏匹配指向具体的已测候选环境。候选若同时修改了奇穴、属性或其他条件，证据中的完整变化仍是复现条件；不能由宏文本匹配推断“只把这段宏贴回原配置也具有相同结果”。匹配不证明收益提高、精确复刻或全局最优。同指纹候选会明确记录未观察到战斗轨迹变化，与未测试区分。

`distill_macro` 的调优结果本次不直接提升为最终宏匹配证据；它仍可能包含需进一步确认的候选。没有满足上述证据契约时，保守显示未匹配，不能以生成器或算法名称替代实际核验。

## 报告协议和兼容性

[`report.rs`](../../backend/src/agent/report.rs) 的生成 Schema 与运行时语义对齐：有正文且不含指标的定性 finding、定性 recommendation 允许空证据引用；数值声明、无正文 finding 和实际循环修改继续受原证据要求约束。

严格输出格式要求所有声明的顶层属性显式存在，`body_markdown`、`artifacts` 分别用空字符串、空数组表示未使用。历史报告仍可省略这两个字段，由原有反序列化默认值兼容读取。Schema 的形状约束不替代本地跨字段与证据语义校验。

`AgentRunResultV1.task_completion` 是带默认值的可选字段；旧会话没有该字段时正常读取。新结果随原有会话记录保存，公开目标文字经过现有凭据脱敏，并按 UTF-8 边界限制在 16 KiB 内。没有迁移或批量重写既有会话。

AI 分析独立页、模拟侧栏及导出报告消费同一份服务端验收结果，显示目标、每项状态、证据 ID 与最终文本散列。该展示不会把 `checks_passed` 解释为模型语义正确率。

## 架构评估与后续优先级

现有设计已经具有模型自主选择工具的闭环、按版本及场景冻结的确定性证据、会话上下文与续问，以及服务端工具权限边界，适合当前受限范围内的战斗分析。没有因为缺少某个 Agent 框架或多 Agent 运行模式，就认定它不符合现代设计。此次补齐的是另一层契约：运行结束后，显式任务条件是否做到、最终产物是否与实测全文一致，以及能分别观察工程、客观任务与语义质量的任务级评测。

后续优先处理本轮已暴露的领域因果审读问题，积累带证据的失败案例，再扩展不同场景、跨版本和隐藏题目的语义评测；同时收敛定性正文与拒答字段不一致等输出协议问题。语义审读需要领域判断，不能以数值校验、关键词、引用存在或一次工具成功替代。

恢复能力需继续准确描述：AI 分析当前提供 replay 与会话 continuation，不能视作同一运行在中断后从持久化检查点精确续跑；武学助手 harness 的 durable resume 属于另一个运行时。若后续确有长任务中断恢复需求，再针对 AI 分析设计持久化状态与工具幂等恢复。本轮没有新增停止策略、累计 token 硬上限或成本控制。

## 隔离环境收尾

测试 worker 已核验可执行文件路径后停止，原有 `public-runtime` 进程未改动。临时 userdata 清理的首次操作被自动审批以 `blocked by policy` 拒绝，未重试删除；目录保留且受 Git 忽略规则覆盖。该清理限制不改变上述固定评测结果。
