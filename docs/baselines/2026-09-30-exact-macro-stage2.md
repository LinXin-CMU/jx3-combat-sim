# 自动提取与目标轨迹压缩（2026-09-30）

用户操作仍是“读取循环并开始”。第一阶段不以字符数为目标；宏通过完整独立回放后，自动进入第二阶段。实际运行不需要已知紧凑解 B，B 仅可用于离线算法调优。现有手动循环、宏执行器、固化及对照操作保留。

已发布 `v2.1.0-20260930.16`，缓存版本 `20260930-stage2auto1`。服务切换前确认无运行中的用户 worker；已保留旧可执行文件回滚备份，校验部署文件散列与在线健康状态。测试 worker 和临时 userdata 已清理。

## 验收合同

进入第二阶段时固定原始完整场景、目标主动施放轨迹、终点、第一阶段最终时间容差和验收类型。所有压缩候选从 t=0 开始交给 Rust 宏解析器与执行器；失败时可提前停止，成功必须另做一次完整回放。要求 `status=ok`、`reproduced=true`、`completed_full_replay=true`、未截断。每步始终与原始目标比较，不积累容差，也不继续自动放宽。

当前默认验收为技能 ID、实际段名称、顺序、次数、引导跳数/时长及绝对施放时间在指定容差内。状态快照单独报告，不把本功能描述为所有内部状态或伤害完全相等。没有引入步骤计数或宏外控制条件。

字符目标采用可复制文本的 UTF-16 长度，与宏草稿界面的 JavaScript `.length` 一致，包括空格、括号和换行。不在验证后去除括号、改写比较运算符或数字。未设 128 字符硬限制。

## 搜索路线

1. 先尝试删行、删条件、同动作交集合并，以及经完整验证的 `/fcast` 转 `/cast`。
2. 以通过宏自身轨迹上的决策和等待状态构建条件、可释放性、允许动作位集。按真实首个有效规则计算选择区域；不可释放动作和低优先级规则不会被误标为必须条件为假。
3. 在允许的原子条件目录内寻找更短的替代合取条件；可替换整条条件，也可同时删除两条旧规则、加入替代条件并移动优先级。
4. 对耦合规则进行局部字符加权 SAT：固定窗口外的规则，联合选择窗口内动作、条件和顺序，要求成本下降。原型使用最多 3 个槽位、每槽位 3 个条件；保留旧条件，加最多 24 个短特征，超过 64 个条件的窗口跳过。单次检查 1000ms，最多 3 个不同模型；明确记录 SAT/UNSAT/UNKNOWN。这些限制仅控制第二阶段局部搜索，不限制第一阶段表达规模或整个任务运行时长。
5. 局部停滞时，用宽度 4、深度 2 的小 beam 保留经验证的等长相邻换序宏，尝试后续更短改写。等长中间候选不会覆盖用户的最短已验证宏。
6. 每次有严格更短且通过回放的结果，更新最佳宏并重新进入基础压缩。有限邻域耗尽后结束该轮；不宣称全局最短，也不把局部 UNSAT 解释为整个宏无解。

样本兼容检查只用于安排候选搜索，可能漏掉沿另一调度路径成立的改写。通过样本的删除也不能证明等价：删除未执行行或时间条件可能改变唤醒时刻，因此仍须真实回放。每条通过的替代路径分别使用自己的样本，没有把互斥路径状态合并成无条件约束。本版为单页压缩；体态分页和人工辅助形式留待后续。

## 任务和证据

同一常驻 oracle 完成两阶段。阶段、计数及改变的宏通过已有精简接口发送；相同宏仍按散列省略文本。每次待回放宏可在“当前试算”查看，最佳宏仅显示已验证改进，保留绿色差异提示。暂停、继续、停止沿用同一个任务控制链。中断压缩时保留最后一个证书及宏，输出不会回退到未通过候选。

后端本地留档包含第一阶段 `exact.txt`/`verified.json`、固定的 `compression-contract.json`、逐个压缩候选和回放、局部 SMT 约束及 SAT 状态、压缩摘要、`compact.txt`/`compact-verified.json`。独立完整回放以宏内容散列分别存档，防止最后一个试算覆盖最佳宏的证据。结果包不下载、不进入用户响应。
