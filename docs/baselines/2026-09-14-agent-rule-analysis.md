# 2026-09-14：规则设计分析与会话续接

版本：`v2.0.13-20260914`，Prompt `agent-system/v52`。

## 问题

用户希望讨论把一个心法的第一重奇穴换成另一心法的奇穴，并形成策划分析。旧 Agent 只读取当前已选能力，无法查询另一心法的模拟器定义，反复索要数据库已有参数，最后把规则假设改成宏文本替换。未知技能被跳过后的零差异，也被误用为替换收益。

连续澄清还存在意图漂移：前端把整段助手问题包进用户回复，历史上下文仅保留最近报告，原始策划目标逐渐被助手提出的宏方案覆盖。

## 修改

- 新增通用只读工具 `lookup_skill_definitions`，优先按名称、部分名称或 ID 查询，未命中时按效果描述查询指定版本与心法的技能、未选奇穴和关联招式。默认查询当前版本的两个心法，返回对象身份、描述、资源说明、冷却、系数和定义哈希。不能执行任意路径读取或修改规则；不把复制目录中未开放奇穴的技能视为该心法能力。
- 候选对照在消耗模拟预算前检查新增技能与奇穴是否可用。普通场景的固定层只能选择一个奇穴，混合层最多三个；新增选择不能与同层旧选择叠加。不可用或互斥冲突的候选返回明确错误，不产生虚假的收益证据。已有无效宏仍可诊断与清理。
- 会话单独保留实际用户请求：原始目标和最近补充独立于历史助手判断，并经过上下文压缩保留。已查到的定义在同场景续接时重新核对，纳入确定性调用缓存。澄清回复只发送用户的答案，兼容读取旧包装格式，不改写既有会话。
- 正常取证、上下文交接和报告修复在工具及诊断状态之后重申实际用户任务，防止最后出现的旧判断覆盖设计前提；收尾也保留完整任务，而非只回答最后一句简短补充。
- 初始自动上下文只给版本、心法与配置背景；完整宏、操作和执行语义由模型按需调用 `get_current_scenario` 读取。完整证据和缓存保持原样，避免所有问题都被自动带进宏诊断。
- Prompt 根据原目标与补充继续工作，先查询可用定义再决定是否缺信息；识别操作调整与规则移植的区别。模型自主组织设计文章、产品提案或机制推演，可明确合理假设后继续，无专用策划模式、固定文章模板或针对某个奇穴的路由。
- 移除续接时无条件推荐宏实验的提示。文章里的未来验证建议和 Markdown 附件不再视为可执行宏候选，明确的只读行动仍可自主继续。
- 定义参数可引用相应工具证据，正文不再误删有依据的资源数值和百分比；未取得实测结果的提升比例仍被拒绝。证据压缩保留完整引用标识；嵌套序列化的报告只显示正文并继续校验数值。
- 数值校验若需要删改正文，先进行一次有证据约束的模型修复，补齐引用或改写为定性说明，保持段落与指代完整；修复后仍不通过才保留可验证部分。复用既有修复与时间预算，不增加无界重试。
- 修正苍生铸世测试服的诊断赛季标记及反馈包会话标识；提及源心法不再改写冻结目标的身份。定义查询也进入模型工作状态和证据压缩，参考资料的诊断摘要保留资格标记。

跨心法规则移植尚未开放为定量实验。定义查询支持分析源机制，不能证明移植后的 DPS；文章应说明设计假设和因果，而非通过无效宏替换伪造 A/B。

## 验证

Rust `cargo check` 通过；477 项测试通过、1 项原有忽略。新增跨心法查询、效果关键词回查、不可用目录过滤、预算前拒绝无效候选和同层冲突、旧宏修复兼容、会话意图保留、模型证据压缩和正文数值引用回归。JavaScript 语法和脚本 setter 静态检查通过。

浏览器澄清控件在独立页面和侧栏均只发送实际答案，续接原会话，保留未发送草稿；自由正文、表格及 HTML 转义正常。

真实模型评测脚本为 `tools/agent-rule-analysis-eval.py`。它接收操作者提供的冻结场景，在隔离 worker 连续提问，保存报告供人工审读；自动断言只检查必要条件，不代替文章质量判断。输入和真实会话副本不进入 Git。

工具离线评测20/20、非法写入0、userdata不变且运行态恢复；模型离线评测12/12。

首轮真实复测作为失败案例保留：查询入口虽已可用，但模型仍以未选技能和无效宏解释规则假设，甚至再次尝试宏替换（已被服务端拒绝，未运行模拟）。因此继续调整假设前提的处理、目标心法身份及定义证据的工作状态后重测，不能仅凭工具调用成功或报告完成状态判定质量通过。

中间复测还发现同层奇穴可以追加叠加，模型误把非法组合的结果当成断马基线。已补上执行前互斥校验：允许模型自主尝试能力探查、纠正选择后计算合法的断马基线；这些结果不能充当阵云移植后的收益。评测同时检查工具参数、错误、证据与正文，不把“零工具尝试”当成模型发挥的成功标准。

第七轮已满足无追问、无宏替换实验的自动断言，但人工审读仍判失败：续接正文以未启用的当前技能解释假设，并提出不自洽的资源上限与强化门槛。因此在诊断状态之后重新传递实际用户任务，继续复测。自动通过不能代替语义审读。

最终 Flash 三轮的交互回归通过：均直接完成正文，澄清次数为 0，宏替换对照次数为 0，使用了跨心法定义查询。耗时分别为 92.6、74.4、104.0 秒，合计 371773 tokens。状态为部分验证、完成、部分验证。输入依次为原始策划请求、只替换第一重的补充、要求自行查库的补充。

人工审读仍未达到策划定稿标准：存在把当前未启用技能当成候选基线、资源移植范围推断过度、手算估值不一致及误读系数字段的问题。此处只把交互与执行边界记为通过，不把模型文章的语义正确率记为通过；结构与引用校验通过也不等于设计论证正确。

使用已配置的 Pro 对同一首题做单题控制：无追问、无宏替换实验，耗时 339.5 秒、151432 tokens，状态为部分验证。文章仍误读资源作用及 GCD 限制，未表现出足以替换默认模型的可靠性提升。控制测试只运行首题，不构成 Pro 多轮续接评测；默认模型设置保持不变。
