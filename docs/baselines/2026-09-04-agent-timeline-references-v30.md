# Agent 技能轴语义引用 v30

日期：2026-09-04

## 问题

手动循环 UI 使用可缩放、自动换行的技能块，因此“第几行”会随容器宽度和显示模式变化。同名技能还可能在循环中出现多次，按技能名高亮会把无关位置一起选中。

反馈 run `run-1a06a981296-3` 中，模型把稳定的 `sequence_index` 表述成“行20”，用户看到的视觉位置与模型语义不一致，也无法直接回到对应技能轴核验。

## 实现

- `inspect_rotation_input` 为每次手动操作返回 `anchor_id=sequence:<index>`、零基 `sequence_index` 和一基 `operation_number`。
- Prompt v30 要求位置判断使用具体出现次数；同一句可以绑定单点、连续区间或多个非连续位置。
- 模型使用 `[[自然文本|op:24,57,91]]` 作为传输标记。操作编号只存在于模型协议和调试信息，前端隐藏该标记。
- 前端按当前模拟结果把稳定操作索引映射到实际 cast time，不使用 UI 宽度、换行或缩放推断位置。
- 用户看到自然文字和 `31.42s` 一类时间标注；悬停显示局部技能序列，多处引用分别展示。
- “在技能轴中标记”会打开循环模拟页、展开时间轴、水平居中目标事件，同时在输入序列中居中并高亮同一批具体操作。
- 旧手动循环会话中的“行20”可兼容为单点引用；宏文本保留真实源码行语义，不套用该兼容映射。

## 验证

- Rust：264/264 tests。
- Agent 工具评测：20/20，非法写入 0，userdata unchanged，runtime restored。
- Agent 模型级离线评测：12/12，证据引用率与工具边界通过率均为 100%。
- `node --check frontend/app.js` 与 `node --check frontend/agent.js` 通过。
- 数值校验器将传输标记中的操作编号识别为导航 ID，不把它误判为战斗数值声明。
- 浏览器验证：单点引用解析为 `0.94s`，点击后仅高亮 1 个时间轴事件与 1 个输入技能块；旧会话引用可正常渲染。
