# Agent 模型主导循环基线（2026-09-04）

## 目标

把固定任务路径与检查点驱动的编排改为模型主导循环：模型理解目标、维护可变计划并自主组合只读工具；确定性模拟器与版本知识库继续负责事实。

## 当前实现

- 单一系统提示词：`agent-system/v28`，约 3.8 KiB。
- 删除 v1-v26 叠加提示词与旧 `reasoning.rs` 检查点状态机。
- 路由仅生成后台观测标签和失败兜底，不进入模型上下文，也不限制工具目录。
- 新增 `ask_user_question`。需要用户选择时返回 `needs_user_input`，回答后沿用同一 `session_id` 继续。
- 供应商常见 JSON 同义字段在适配层无损归一化；数值、证据 ID、版本与来源校验保持独立。
- 上下文在 48 KiB 提前压缩，72 KiB 为最终硬上限；证据交接优先保留领域定义、当前场景、完整小型姿态宏与最新公开工作摘要。
- 当前版本领域实体参与混合检索排序。同一文档去重前，用户明确提到的实体定义段优先；“白刀”回归命中 `fs-white-blade-001`。
- 供应商工具参数异常时，已有多项证据则转为模型整理报告；证据不足时重新选取动作。

## 真实模型观察

- 模糊问题“帮我比较一下它们”由 DeepSeek V4 Pro 主动询问比较对象并暂停，证明澄清链路可用。
- “按攻略哪里可以插白刀”能够识别三种不同任务口径，并通过 `ask_user_question` 让用户选择手动窗口、修改宏或定位现有宏。
- 历史失败中，请求达到 67.8 KiB 后超时；提前压缩后的同类运行最大请求为 42.4 KiB。
- 真实回归仍暴露一个待实现工具缺口：逐次定位宏运行中的技能与 Buff 层数需要可查询的事件窗口。模型能够识别该缺口，但现有聚合时间轴不足以完成逐刀归因。
