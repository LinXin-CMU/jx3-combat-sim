# Agent 动态诊断首轮检查点（2026-09-05）

> 历史检查点：本文记录 v35 的实现与评测，其中固定任务路径、白刀专用统计和专用事件入口已在 v38 重构中删除。当前基线见 `2026-09-05-agent-model-led-v38.md`。

## 目标

把循环分析从固定任务路径改造成可回退、可追问、可自行验证的“诊断—验证—结论”循环。模型负责形成判断与选择动作，模拟器负责确定性事实、局部候选和同场景 A/B；报告校验器只约束可验证事实的证据归属。

## 已实现

- 运行时维护 `AgentDiagnosticStateV1`：用户目标、当前判断、已知事实、依据、开放假设、最小证伪实验和最近动作。
- `analyze_timeline` 增加循环阶段、绝刀怒气档位、援戈流转、真实溢怒来源、白刀分布、宏行命中与循环形状。
- `compare_scenarios` 支持在冻结完整宏上执行局部 `macro_replacements`，并返回两侧完整诊断。
- 白刀位置一次返回完整轻量索引，并按血怒内外和宏语句分组；详细上下文只做分层抽样。
- 模型上下文只传诊断摘要，完整 Evidence 和 provider 响应留在私有 replay；同参确定性调用复用。
- 报告缺失 evidence id 时按本轮事实补绑定；数值仍由服务端验证，玩法判断可作为机制判断或假设保留。
- 比较结果增加确定性的阈值方向和差值方向：例如 `bufftime:嗜血<5.3` 改为 `<5.0` 是满足区间缩小、随倒计时更晚满足；正负 DPS 差不再交给模型自行猜符号。
- `ask_user_question` 只接受真正缺少关键用户事实的追问。把“无需作答”“你更关心哪种展示”“要我继续验证吗”包装成追问会被协议拒绝并要求模型完成报告。

## 本轮证明与未证明的部分

已经证明：动态状态能够驱动模型自行运行工具与 A/B；局部宏替换可用；精确事件不再受 UI 排版影响；上下文体积已受控；真正缺少保存方案名称时可以正确追问。

尚未证明：开放诊断能稳定形成专业主判断；宏逐行和等待语义足以让模型一次读懂；白刀逐次分类不会被模型二次改写；所有已完成实验都能稳定进入正式报告；端到端时延达到产品可用水平。

## 下一轮建议

优先补模拟器语义与编排，而不是继续扩写 Prompt：

1. 为等待、宏行和白刀事件生成确定性的归因标签与完整轻量索引，减少逐事件翻页和模型自行重建分类。
2. 让 orchestrator 把“已完成实验但报告未提交”作为协议状态处理；拒绝伪追问后只允许正式报告，不重新开放无关工具。
3. 将开放诊断拆成服务端可复用的紧凑诊断快照；模型在其上提出一项假设和一个候选，避免 90k token 的重复证据回灌。
4. 只重跑 D01、D03、D04、D05、D06、D09、D11、D12；这些通过后再跑第二轮完整 12 题。

此处是重要确认节点。下一轮应以人工可用率和中位时延为验收指标，不以自动 12/12 代替质量判断。
