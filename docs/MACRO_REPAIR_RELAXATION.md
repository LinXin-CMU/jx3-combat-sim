# 分歧改法：条件放宽与验证

候选只从模板技能轴快照提取，不读取原宏作为正确答案。草稿仅用于定位修改行和保留其余宏上下文。

## 已实现

| 规则 | 示例 | 边界 |
|---|---|---|
| Buff 剩余时间转存在 | bufftime:血怒>5 → buff:血怒 | bufftime 在不存在时为假；去掉时间限制会扩大成立范围 |
| 目标 Buff 剩余时间转存在 | tbufftime:流血<3 → tbuff:流血 | 同样会丢失临近结束窗口，必须试跑 |
| 正层数转存在 | buff:血怒>=2 → buff:血怒 | 仅处理排除零层的 >、>=、=；不把 =0、<3 等转为存在 |
| 删除组合子条件 | A&B → A 或 B | 由后端语法树生成，避免改变右结合语义；OR 删除分支属于收紧，不能声称放宽 |
| 移除全部条件 | /cast [A] 技能 → /cast 技能 | 作为最大放宽对照，不默认应用 |

存在转换仅对完整原子式执行；组合先由后端删减，再对产生的原子式尝试转换。结果不继承原条件的命中统计，明确标注整轴验证。

## 可扩展但尚未实现的规则

- 怒气、暴怒、格挡与充能阈值：从正反样本相邻边界调整，例如 >80 尝试 >70。需要重新评估误触发，不能随意固定减一个常数。
- 等值条件转区间，例如 sun=100 尝试 sun>=100 或 sun>某个样本边界；上下限方向均需比较。
- 同一 Buff 的时间与层数联立限制，先删一项，再扩大剩余项边界。
- OR 增加分支会放宽，但容易产生过拟合，应限制条件数并使用独立场景验证。

不能把 skill_energy>0 直接视为技能可释放，也不能把剩余时间小于阈值视为 Buff 不存在；冷却、体态、资源与 Step 2 可释放性仍由模拟器判断。last_skill 条件和资源条件之间没有通用蕴含关系。

## 执行与展示

原子建议先试跑，再生成组合与删减建议。按整宏文本去重，单次最多验证 24 条，并复用当前冻结场景的模拟缓存；焦点或草稿变化后旧结果不更新界面，不继续派发旧批次。每条验证完成立即新增一个标签页，当前阅读的标签不因后续排序而切换。

所有候选使用相同环境完整模拟。按新增技能分歧、总技能差异、时间偏差、宏长度排序。应用仍需点击“应用到草稿并重跑”，不修改正式宏。当前场景的序列等效不代表所有装备、延迟和战斗时长均等效。

## 简化方案合并

24 是内部试跑预算，不是要展示的条数。每条完成后，比较完整时间轴（忽略宏页码和行号）、DPS、战斗时间和跳过动作；全部相同才淘汰条件项更多的方案，同项数时保留文本更短的版本。伤害、时间或状态不同的方案不会仅凭差异数量相同而合并。被替换的标签立即删除并重新编号；如果正在查看该标签，切换到它的简化版。

这一步需要完整状态快照，因此自动改法验证继续使用 full。已有仅需要 DPS 的调用继续使用 lite，不为统一模式而丢弃验证所需数据。

展示过滤：只保留无新增技能分歧、且技能差异减少或技能序列等效而文本更短的候选。按原排序最多展示 5 条；其余直接移除，没有有效候选时显示空结果说明。

## 连续差异段的多行验证

点击分歧后，以当前对齐行向两侧扩展连续红/绿段。技能差异模式仅纳入缺失和多放；状态模式同时纳入状态差异。联合候选优先验证，单行候选仍参与同轮比较。

模板侧使用已有 `/api/macro/assist/program` 联合搜索（含组合外同技能负样本和行间冲突）；只有一个模板技能时使用单技能条件搜索。实际侧多放、且不在本段模板中的技能，按模板中的全部释放位置提取限制条件；模板完全未使用的技能尝试删除语句。各项修改合成为完整宏后统一 full 验证，不能把单行得分相加当作多行验证结果。

保留页头、注释、无关宏行和 cast/fcast 释放方式；技能分布多个页或混用 cast/fcast 时明确提示歧义。接口上限为 32 步；前端为限制单次耗时按最多 8 步分块，生成后合并整个范围，各块候选按名次组合为最多 3 个整段方案，不声称穷举或全局最优。多行改法与单行改法共用内部试跑预算、效果过滤及最多 5 个展示标签。每条结果附整段模板技能匹配数。

验证：纯函数检查连续段边界、多行原位合成及无关页/注释保留；真实浏览器使用模板三步组合经联合搜索生成多行宏，再调用真实诊断接口完整模拟。布局重绘保留两侧滚动位置，避免清空序列 DOM 后滚动归零。

## 2026-09-11 操作与在线耗时

操作由左侧页签决定：候选条件页启用十字准星和技能框选分析，宏草稿页沿用普通序列操作，单击红色技能查看分歧诊断。不再按红色与否在候选条件页抢占单击事件。

条件搜索请求仅投影后端 InputCast/InputState 消费的字段，保留零值、未知状态、永久 Buff、资源及技能状态；不上传伤害、state_after、属性快照等无关字段。full 模拟及完整结果比较不降级。

改法请求在浏览器内串行派发，旧焦点尚未派发的任务不进入后端；已派发请求等待完成（浏览器取消并不能保证中断服务端计算）。超过 60 秒按实际阶段提示失败。长段按 8 步分批联合搜索，仍合成整段宏完整验证。

在线只读 300 秒自建样例：原始条件请求 2,904,781 字节 / 6773 ms；精简请求 1,215,224 字节 / 2898 ms，响应文本完全一致；full 候选验证 327 ms；8 步联合搜索 3668 ms，均 HTTP 200。本次样例未复现用户的 60 秒超时，因此不能据此声称所有场景都不会超时。未停服、未调整服务端超时阈值。

## 2026-09-11 阈值漏搜与验证误淘汰

发现并修正：

1. 缺失技能按模板释放前时刻寻找诊断轮次，不能默认绑定后续实际动作。额外释放仍按该次实际执行精确定位。
2. 原宏只是待修改的起点。根据模板目标技能状态、其他技能状态以及实际多放该技能的快照，对已有 rage/sun/energy、Buff 时间/层数、充能等数值原子枚举观测值附近的双向边界。不使用任何技能名特判，也不引用“原来正确宏”的条件作为答案。
3. 同时保留原位置修改、修改后前移的假设，完整试跑决定是否需要顺序变化。静态新条件按字段族保留多样性，不只取总体前两条。
4. 原“新增多放”依赖左右相邻模板索引，补回缺失动作后相邻索引改变会误报。现在额外比较修改前后实际动作轨迹，对已存在的额外动作沿用身份；真正新增的额外动作仍淘汰。重复动作的身份依然受 LCS 对齐的不确定性影响，不据此宣称严格因果证明。

新增纯函数回归覆盖缺失锚点、无技能名假设的收紧/放宽、阈值与前移组合、修复缺失后保留既有额外动作及发现真正新增动作。真实浏览器构造 60 秒反事实样例：盾回 rage<30 延至 13.875s；只改 rage<50 保留原顺序即可在 12.5s、35 怒返回。通用状态阈值候选也能恢复该次返回。不能假定前面技能条件成立就一定抢先，Step 2 仍检查可释放性；是否需要前移由模拟结果决定。

上述是自建同类问题的验证，截图未提供完整场景，因此不声称精确复现截图的全部 298.9 秒状态。

## 同轮关联技能复查与两行改法

对目标之外的实际选中技能、缺口后续实际技能（去重，最多两个），使用同一冻结请求重放同一时刻，复查其全部宏条件和可释放性。关联复查必须匹配原 fingerprint、判定时间、页、选中行、上次技能和怒气，未匹配就提示证据不足，不能使用后续时刻冒充同一轮。界面展示关联行的语义条件、原子真假、实际值和 Step 2 原因。

目标条件不成立且此刻可释放，才优先搜索能跨过当前阻断数值的边界；若同时受冷却等限制，不将单改条件描述为直接修复。实际选中另一技能时才提出“限制该行”的直接假设，其他关联行仅作为搜索方向，不断言它抢先。

目标与关联技能的新条件按轮次交替取样，避免目标行独占全部预算。支持两条不重叠宏行的联合候选，每条都从冻结原宏重新合成并独立 full 试跑，不将单行分数相加。仍保留单行、阈值、顺序、整段候选并统一过滤和排序，最多展示五条。

回归覆盖：角色判定与可释放性限制、同轮关联显示、两行合成及冲突编辑拒绝；原真实宏阈值反事实与四种配色检查继续通过。该实现没有任何针对绝刀、盾回的条件规则。
