# 写宏工作台设计 v2

状态：下文保留 2026-09-09 设计稿。2026-09-10 用户授权重排写宏模式，当前布局为上方模板/实际对照，下方左写宏、右诊断或选段候选条件；目标技能两步复查与候选全窗口试跑已实现。当前实现与验证见 [宏分歧诊断基线](baselines/2026-09-10-macro-diagnostic.md)，以下旧布局图及“后续设计”不作为已实现事实。

用户目标：以手工编排的循环为模板，在同一页面选技能、写宏、运行宏、查看实际循环与模板的差异，逐步修到符合预期。单选产出单行候选，多选产出完整多行方案，逐步条件分析作为解释和微调依据。

已实现能力与边界见 [MACRO_ASSIST_DESIGN.md](MACRO_ASSIST_DESIGN.md)。[早期独立线框稿](prototypes/macro-authoring-workspace.html)仅保留为逻辑讨论的示例，不再作为最终布局方案。

## 1. 产品主线与页面布局

主线是「模板 → 选定写作目标 → 编辑草稿 → 运行对照 → 定位差异 → 修改草稿」。建议条件只是写作材料，实际运行反馈是主要完成标准。入口及原页面结构保持，新增区域仅在写宏模式显示。

```text
编辑序列 / 写宏       共用环境 · 对照时长       [运行对照] [更多]
┌───────────────────────────┬───────────────────────────┐
│ 模板循环                  │ 宏实际循环 / 差异对照     │
│ 单击、框选；保留原编排    │ 实际释放、按层显示差异     │
│                          │ [第一处差异] [上一处/下一处]│
├───────────────────────────┼───────────────────────────┤
│ 原写宏助手                │ 新增宏草稿                │
│ 单行 / 多行方案            │ 编辑、撤销、复制、运行     │
│ 插入草稿、展开证据         │ 差异详情、对应宏行        │
└───────────────────────────┴───────────────────────────┘
点击差异：在侧栏展示两边状态、相关宏行、实际执行证据
```

- 直接扩展现有写宏模式，左侧模板与写宏助手保持原位置；不另建工作台页面、品牌头或独立视觉体系。
- 两侧标题在共同顶部栏，序列顶边对齐；三条分隔可调整上下高度及各排左右宽度，支持键盘微调、双击复位和比例保存。同步滚动默认开启，可关闭；显示控件不覆盖技能。
- 右下编辑器保持可见，左下候选数量先少后多，长证据收在详情内。宏草稿与差异详情在右下区域左右并列，内部可拖动分隔调整宽度并保存比例，双击均分；未显示详情时草稿占满宽度。
- 宏草稿自身分为左右两栏：左为盾宏/通用宏，右为刀宏，两栏共用载入、撤销、复制和运行按钮。已有草稿从首个刀页开始放入右栏，标准 `#page shield/blade` 行从输入区隐藏，分页仍由程序保留用于运行；新写的右栏自动采用刀姿态分页。首次创建刀宏时，为尚无显式分页的左栏采用盾页，避免通用页遮蔽刀宏；该变化可与输入一起撤销。复杂分页保留顺序并提示，不能为了界面分栏丢弃或重排原宏。
- 新控件、差异背景带、选中高亮、编辑器背景使用现有主题变量，覆盖暗色、樱花、米白和靛青设置；技能图标、名称、资源和角标调用原序列渲染，不复制另一套外观。
- 当前在 900/1440 宽度保留四个原位区域，缩小时限制最小可用尺寸并允许区域内滚动；窄屏重排仍属后续设计。
- 运行前右侧为空态；运行后保留上次结果，清楚显示其是否对应当前草稿和配置。

## 2. 模板、草稿与结果的生命周期

三个对象独立保存：模板及其完整环境、宏草稿、某个确定版本草稿的运行结果。

- 进入写宏模式：继承当前模板和环境，恢复本模板工作草稿。首次进入可从已有宏导入，或从空白开始；查看建议不会改动草稿。
- 返回编辑模式：保留草稿、选择、光标和结果。修改模板/环境后刷新左侧与建议，旧对照标记“模板或环境已变更”。
- 手工改宏：即时显示语法/字符反馈，右侧标记“草稿已修改，尚未重跑”；不因每次输入触发整宏模拟。
- 主按钮“运行对照”，快捷键 Ctrl+Enter。先固定本次模板、环境和草稿版本，再运行；结果晚到时只归属该版本，不能覆盖更新后的草稿或冒充最新验证。
- 建议分析自动更新、选择立即反馈；整宏运行默认手动。未来可提供默认关闭的停笔后运行，但必须合并请求并受计算预算限制。
- 运行中保留旧对照和选中高亮，显示进度；失败/超时保留草稿，提供重试。取消请求与服务端取消计算的边界应明确实现。
- 草稿按用户、版本/心法和模板工作项隔离；切换到其它心法不会携带旧版的“已验证”标记。初期可用现有浏览器侧草稿机制，正式存档沿用既有宏保存入口。
- “复制宏”只导出文本；“保存为宏方案”是明确动作。插入建议和模拟结果都不能自动覆盖正式宏、模板或既有用户存档。

## 3. 选择与建议

### 单选

点击一个主动技能，立即高亮并显示“正在写：技能名”。沿用用户此前确认的规则，在模板中查找该技能的全部释放，返回单行宏候选。

展示主候选的可复制语句、模板位置覆盖、可能额外成立的位置与字符数；状态和其它等效写法可展开。如果单个技能的全部出现都已作为正样本，不虚构“组合外同技能”负样本，明确说明该对照组不存在。

### 多选

框选连续组合后，立即显示组合，并查找全部同序连续出现位置。默认返回数个**完整多行片段方案**，每个方案同时展示整个文本、所选组合的联合覆盖、组合外同技能条件成立情况、行间冲突与总字符数。

每步条件仍需计算，但放在“查看每行依据 / 换一种条件”详情中。宏不是顺序脚本，不能用“每步第一名直接拼接”代替整段搜索和评价；也不能把重复技能简单重复写成多行就视为可顺序执行。同技能分支只有在完整作用范围和行优先级允许时才能合并。

建议生成分两层：

1. 模板快照初筛：从各步候选构造有限数量的整段方案，比较各处组合是否都能被识别、组合外反例、可观察的行间冲突与字符成本。
2. 运行验证：把准备采用的方案放入明确的草稿位置，在当前草稿上下文中运行；是否复现组合、是否影响其它位置，以真实对照为准。未运行方案只标记“模板状态匹配”，不能标记“已验证”。

验证标记绑定实际运行的完整宏文本、模板、环境和范围。当前草稿通过不意味着其它未插入运行的替代候选也通过，局部片段成功不能继承为整宏成功。

联合排名优先满足用户的写作范围；有运行证据的方案按复现效果、首次分歧、额外释放/缺失、关键资源与时间偏差排序，效果相近时再考虑字符和条件复杂度。不会因 DPS 高一些就排到更符合模板的方案之前。

### 负样本的作用

- 保留三组对照：全部匹配组合外的同技能、组合内其它步骤的同技能、其它技能。
- 写一个组合专用片段时，组合外同技能是主要反例，不能被大量其它技能稀释。
- 显示“组合外条件也成立”，并检查该行是否真的抢占或额外释放；条件成立和技能实际误放分别计数。
- 整份宏可能用一条通用规则同时服务组合内外。若模板本来就在外部位置要求该技能，完整宏正确释放它不算错误。不能为了消灭片段反例，反而破坏整条循环。
- 没有组合外样本、快照字段不足或条件无法区分时，明确标记证据不足，不用猜测补齐。

## 4. 宏编辑器与采用建议

编辑器至少支持：行号、现有通用/擎盾/擎刀页语义、语法反馈、当前页字符数、撤销重做、光标插入、选中文本替换和复制。字符/分页预算沿用项目现行宏编辑规则，不能通过偷偷分页改变执行方式。

- 候选默认操作为“插入光标处”；只有编辑器确有选中文本时提供“替换选中内容”。一次多行插入作为一次可撤销操作。
- 插入前可看文本变化及插入位置，插入后高亮新行并标记“尚未运行”；不自动调整用户其它行的顺序。
- 同技能已有行时提示可能重叠，并提供查看位置；不直接认定重复或自动删除。
- 用户修改了生成片段后，后续分析刷新只更新建议区，不重写该片段。生成来源和位置关联允许失效，不能错误替换旧行号。
- 选择另一组合只改变写作目标，不清空草稿。可逐段加入同一份宏，随后运行整宏检查相互影响。
- 保留现有约束：Buff 使用真实名称/别名；生成的 `bufftime` / `tbufftime` 最多一位小数；暴怒为 `sun`，格挡为 `energy`；测试服阵云/月照/雁门保持独立。

## 5. 两种运行范围

| 运行方式 | 输入与用途 | 结果含义 |
| --- | --- | --- |
| 运行对照（默认整宏） | 从相同开战环境运行完整草稿，至共同对照终点 | 评价草稿能否还原整个模板；包含草稿中其它行的干扰 |
| 试跑选段（次入口） | 在模板每处所选组合之前重放前缀，再让所选宏片段接管局部窗口 | 评价这一段在模板上下文中是否可行；不等于整宏已跑通 |

整宏运行是最终完成标准。草稿只写了一部分时依然显示真实运行结果，同时标记“草稿编写中”；可以聚焦当前目标，不能伪造其余部分已由宏执行。

局部试跑用于解决从空白写到循环中段时缺少前缀的问题。局部结果明确标出“模板前缀 / 宏试跑区间”，显示每处命中的成功与失败，不能挑其中一次成功作为全部成功。片段外反例按独立对照窗口检查，不能只从正样本起跑。

局部试跑须用原有模拟链重放前缀或在模拟器内部创建完整 checkpoint，保留计时器、Buff、充能、姿态、团辅进度和内部脚本状态；不能靠把公开 `state_before` 的怒气/Buff写回去拼一个状态。局部窗口结束后不将已经偏离的状态接上手工后缀并宣称宏复现了整循环。

## 6. Redline：技能对齐后的差异视图

### 匹配与显示

主要对齐对象是成功主动释放，包含非主 GCD 技能；被动触发事件折叠到所属位置，不挤占主要对齐序号。等待、手工清 CD/移除 Buff、指定偏移和引导控制另标为模板控制点，不伪装成可直接输出的宏技能。

两边采用技能身份及顺序的序列对齐，最长公共子序列优先保留同技能匹配数量，同分时参考总时间距离。右侧只显示实际释放，不插入缺失技能的虚框；模板缺失项直接在左侧标记。不能直接用数组下标比较，也不能按最近时间任意串到下一轮。

默认只突出技能缺失、多放与顺序差异，“含状态差异”再显示同技能的时机、资源与档位变化。双方各自保持真实技能序列，点击技能定位对应事件和详情；视觉位置相近不表示同一时刻。未来的时间坐标和对齐歧义诊断不能以当前排布冒充已实现。

默认保留技能身份，怒气档位、等级、引导跳数作为同技能的差异属性。阵云、月照、雁门以及独立雾海技能不相互折叠。宏行号、技能 ID、主动序号和时间分别保留，保证点击定位不混淆。

| 差异 | 表现 |
| --- | --- |
| 一致 | 正常技能块 |
| 模板有、宏缺失 | 左侧红底，右侧没有对应技能块；可点击或用首处差异定位 |
| 宏额外释放 | 右侧绿底，左侧不插占位；不额外添加“多 / 差”角标 |
| 顺序发生变化 | 展示插入/缺失关系，可明确配对时再标“顺序变化”；不把任意相邻不同技能强行叫作替换 |
| 同技能时间不同 | 默认不着色；打开状态层后左红右绿，详情展示早/晚时间 |
| 同技能资源/档位不同 | 默认不着色；打开状态层后左红右绿，详情并列展示真实资源和技能信息 |
| 未运行 / 结果过期 / 窗口外 | 灰色状态和文字说明，不混入本次错误计数 |

相邻同色标记在同一显示行连成背景带，遇到正常技能或换行截断；背景采用主题红/绿 45% 混色，图标保持不透明，通过汇总计数与点击详情查看差异，不再添加“多 / 差”角标。一次少放技能不能让后面全部技能因数组下标偏移而变红。原始时刻与差值始终可查，数值容差只影响突出显示，不篡改运行记录；累计偏移与新增等待的因果区分仍需后续决策证据。

首处差异按当前选择的层级定位，只有隐藏状态差异时默认禁用。同步滚动默认开启，按两侧各自可滚动距离的比例联动，可关闭；点击差异对应定位优先，不被同步滚动拉走。上一处/下一处及聚焦选段仍属后续设计；没有因果证据时不把第一处可见差异叫作根因。

### 点击差异后的反馈

详情逐行并列显示技能、时间、怒气、暴怒/格挡、Buff 层数/时长和冷却/充能，只有不同字段染红/绿，相同内容保持原样。Buff 以身份匹配，重排不会误报差异，单侧存在的记录也保留；按显示精度比较时长，缺记录不补零。右侧实际释放带宏页/行定位；来源语句、定位按钮与说明放在带间距的独立底部区域。

行定位绑定本次运行的宏文本版本，解析器保留语句到编辑器物理行的映射（包含空行/注释影响）。草稿已改时提供“查看本次运行文本”或可靠映射后的定位，不能把旧第 3 条语句直接跳到新稿第 3 行。

诊断按证据分层：

1. 实际发生了什么：模板期望与实际技能、时间、资源的差异。
2. 该决策点记录了什么：目标条件不成立、条件成立但技能不可释放、前面的行先执行、该页没有目标行，或没有取得足够记录。
3. 可尝试的修改：跳到相关行、查看反例、收紧/放宽条件或调整优先级的候选。建议不自动覆盖，改后重新跑。

示意：“模板这里是月照，实际再次释放阵云；第 2 行被执行。”只有在相同决策点捕获了第 3 行的条件与可释放性，才进一步说明为何它没有执行。全局某行被跳过的总次数不能证明这一处差异的原因。

判断时刻、释放前快照时刻和施放时刻分别保留。现有执行链会在条件判断后推进网络延迟与 Buff 时间，再采释放前快照；不能把该快照重新算出的条件真值说成当轮原始判断。局部诊断也要记录没有技能释放的等待决策，否则无法解释空转。

## 7. 对照口径与验收标准

### 对照公平性

模板和宏绑定同一版本/心法以及装备、属性、目标、奇穴、秘籍、加速、延迟、初始资源、预释放、团辅、阵法和期望模式等完整环境。环境只设一份；选段、停手及手工控制是各自执行策略，不错误当成双方通用的动作索引。

默认对照范围为模板一遍实际执行的共同时间窗口，用户调整终点时两边一起重算。主动决策终点、边界上施放与引导结束、持续伤害尾段采用同一明确口径；输出共同的评分时长，不能把模板自然结束的 DPS 与宏自行提前停止的 DPS直接做百分比。

建议统一评分窗为 `[0, T)`：`T` 默认取模板完成最后动作所覆盖的结束时刻，界面显示并允许修改；到 `T` 不再接受新的宏决策。因此前决策的延迟或引导跨过 `T` 的部分继续遵循核心结算，但窗口外施放和伤害另列；共同窗口伤害只纳入窗内实际伤害事件，DPS统一除以 `T`。当前 API 的自然结束 `fight_time` 不具备此严格口径，比较模块需显式实现，不能只用已有总伤害除一个新分母。

中间卡住但剩余时间内未再施放仍属于该对照窗口，不能因为右侧事件少就缩短分母。超出窗口的伤害或施放单列；模板自身有跳过/无法执行的技能时先标明，不能悄悄删掉目标并显示宏“完全一致”。

手工模板中的清 CD、人工移除 Buff、指定时间偏移或引导截断可能没有对应宏表达能力。可以对照实际结果，但要指出哪些目标依赖手工控制；不为了追求一致而输出不支持的条件或隐藏这种限制。

### 面向玩家的指标

优先显示：首处分歧、主动技能缺失/多放、目标组合复现次数、同技能关键资源差异；时间偏差与共同窗口伤害/DPS 为辅助指标。若提供相似度，须写清按何种事件对齐计算，不能只用技能次数相同代表顺序正确。

“符合当前模板”只在本次指定环境/范围成立；改变环境后标记需重跑。多延迟/初始资源等稳健性检查可后续加入，不混入第一版主界面。

### 必须覆盖的验收场景

1. 单选立即反馈，返回单行；多选默认完整多行，内部单步分析折叠。
2. 模板含三处组合和两次组合外同技能，正反例展示完整；联合方案不会只在一处成立就标全部通过。
3. 两条各自表现良好的条件组合后互相抢占，整宏运行明确暴露冲突。
4. 少放/多放一个技能后，后续共同序列恢复对齐；重复技能和相邻循环不发生跨轮误配。
5. 阵云前暴怒档位不同但技能名相同，显示资源差异；月照与雁门保持独立。
6. 稿件仅完成一段可进行局部试跑，结果不获得整宏验证标记。
7. 修改模板/草稿/环境后旧结果标记过期，晚到响应不覆盖新内容，切模式和刷新分析不丢草稿。
8. 实际事件定位宏行正确；缺乏决策证据时不编造“被抢”“资源不足”等具体原因。
9. 双方使用一致窗口和伤害口径；宏卡住/引导跨边界/持续伤害尾段不会产生虚假的 DPS 优势。
10. 普通编辑与正式宏存档不被试跑覆盖；前端布局、键盘操作、撤销和错误恢复可用。

## 8. 实现安排与现有能力

### 建议分两批实现

**第一批，先形成可完整使用的写宏闭环：** 双循环工作台、独立草稿编辑器、单/多选正确输出、明确插入与撤销、完整环境的整宏运行、主动序列 redline、状态/宏行定位、共同评分口径、结果过期保护。这一批必须能从已有宏修改、运行并找出差异；不能只增加编辑框却仍然手工搬结果。

**第二批，补强从空白逐段编写与修复：** 每处选段的前缀重放试跑、组合外反例窗口、完整草稿上下文中的有限联合方案搜索、按首处分歧取得有界决策记录。第一批显示的推断必须保守，不能提前承诺第二批才有的原因定位能力。

### 代码核对后的复用边界

- `frontend/app.js` 的 `buildMacroText()` 已有通用/体态分页语义，可以抽取复用。
- `runMacroSimulate()` 会重建 `#sim_sequence`，不能直接拿来驱动右侧，否则覆盖左模板。新工作台独立持有 `referenceResult` 和 `candidateResult`。
- `Jx3SimulateOnce` 当前服务旧优化工作流，入参没有覆盖主模拟的全部环境，不能原样用作公平对照。
- 旧 `collectCastCounts()` 有月照/雁门合并到阵云的语义，不能用作新 redline 的技能身份或顺序指标。
- `CastEvent` 已有 `sequence_index`、`macro_page`、`macro_line`、前后状态与资源明细，可复用渲染与定位数据。
- `MacroLineExecutionStats` 是全程汇总；现有 `macro_debug` 并没有持续产出完整逐决策记录。精确原因诊断需有界采集或定点重放，不从汇总推断某一帧。
- 比较与局部试跑共用 `simulate_core` / 现有宏执行链，不能另算战斗公式。普通模拟默认不增加整场逐行 trace。
- 建议前端模块分离为工作台状态、宏编辑、对齐视图；后端新增薄的只读比较编排与诊断模块。沿用现有强类型请求、输入大小/事件数/时长预算，测试统一在 `backend/tests/` 和 `tools/`。

下一轮实现前，以本稿的范围与验收项拆任务；本稿自身不触发服务部署或用户数据迁移。
