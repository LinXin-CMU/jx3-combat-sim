# Agent 90 秒作品集 Demo 脚本

录制前：本地启动项目，保持公网关闭；在循环模拟准备一个短循环；使用 `deepseek-v4-pro` 时同时展示 profile/model，不展示 API key；若使用 `offline`，在画面标注“工程闭环演示”。

## 0–12 秒：问题

画面：Hub → “AI 战斗分析”。

旁白：传统聊天模型会给出听起来合理的数值，但战斗策划需要可复现的实验。我把模型限制为规划者，把现有 Rust 模拟器作为事实源。

## 12–25 秒：冻结场景

画面：循环模拟跑一次，回到 Agent；顶部显示已捕获场景、循环类型和网络延迟。

旁白：前端提交完整场景，服务端绑定当前版本和心法并生成 scenario hash。同一轮分析不能悄悄改环境。

## 25–48 秒：运行 Agent

输入：分析当前循环的输出基线，并说明证据边界。

画面：SSE 依次出现“拆解问题、调用工具、取得证据、校验证据、分析完成”。

旁白：模型只能调用四个只读强类型工具。模型轮次、工具次数、候选数和六十秒墙钟都由服务端计数，不依赖 prompt 自律。

## 48–66 秒：检查结论

画面：报告摘要、DPS 证据卡、scenario/prompt/evidence 身份。

旁白：每个数字必须携带 evidence id 和 JSON pointer。校验失败只允许修复一次，再失败就降级为证据不足，未经验证的数字进不了 findings。

## 66–78 秒：恢复与审计

画面：点击左侧历史会话，展示上一轮问题、工具轨迹和报告；点击复制实验摘要。

旁白：会话按用户目录追加保存，不记录 API key、隐藏推理或 provider 原始请求。worker 中断会被明确标记，不自动重发外部调用。

## 78–90 秒：量化与反思

画面：案例页指标表或终端一键验收摘要。

旁白：当前 118 个 Rust 测试、20 个确定性工具题和 12 个 Agent 离线题全部通过。真实固定题集最好六题通过、复跑五题，越权工具始终为零；失败时系统拒绝发布无证据数值，这比只展示一次漂亮回答更重要。

## 必须出现在画面中的信息

- profile 和 model；
- scenario hash、prompt version/hash、evidence id；
- 至少一个工具步骤和一个限制；
- 评测不是单次对话截图；
- offline 演示不得暗示发生了真实模型调用。
