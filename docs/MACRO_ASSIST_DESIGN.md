# 从选中技能辅助写宏

本文记录初版分析与增量实现边界。用户已确定在现有模式左侧保留模板及助手，右上增加实际序列对照、右下增加独立宏草稿；完整逻辑及后续局部试跑设计见 [写宏工作台设计 v2](MACRO_AUTHORING_WORKSPACE_DESIGN.md)。

## 问题与目标

玩家已经手工排好想要的循环，却需要逐次翻看资源、Buff 和技能冷却，才能写出能识别这些释放位置的宏条件。本功能把选中的一个技能或连续组合当作查询，找到当前序列中全部同序出现的位置，并用确定性统计给出可复制的条件。用户于 2026-09-09 确认：多技能按相同顺序的连续组合匹配。

语言模型不参与计算。现有序列编辑、旧“序列→宏”生成器和各版本战斗行为独立保留。

## 交互

1. 编辑器顶部统一切换“编辑序列 / 写宏”，自动取得当前完整环境的状态；已经有同配置完整结果时直接复用。
2. 单击技能，或从一个技能拖到另一个技能选择连续区间；从空白区域拖动则沿用矩形框选。被动显示项不参与选择。
3. 选择后立即高亮并显示所选技能，再异步计算。同一行连续的选中项和其它匹配位置各用整段外框，正常技能和换行截断，不逐个技能画框。单选默认展示单行；多选默认展示完整多行方案，逐步分析放在可展开详情中。
4. 筛选栏后直接展示候选；查看综合排名，或筛选“覆盖全部位置”“无额外匹配”；按 `sun`、Buff 名等搜索条件和其它等效写法。长说明、组合内外对比及出现位置默认折叠，自动刷新保留展开状态。
5. 查看全部出现位置的各步释放前状态；展开候选证据，定位已覆盖、未覆盖和额外匹配的位置。
6. 将单行或完整多行方案插入右下草稿，或复制；“运行对照”在同一完整环境下运行草稿，右上用原技能序列样式显示实际结果与 redline。保留所选组合、草稿和结果，切换模式可继续。
7. 默认仅突出技能缺失、多放与顺序差异，可切换“含状态差异”查看时间、资源及技能档位变化。右侧只显示实际释放，缺失技能直接标在左侧；同一视觉行相邻的红/绿标记连成背景带，图标保持不透明。主题红/绿按 45% 混色，不添加“多 / 差”角标。
8. 三条分隔线调整上排左右宽度、下排左右宽度和上下高度，支持拖动、方向键微调、双击复位并保存比例。两边标题共用顶部栏、序列顶边对齐；同步滚动默认开启，也可关闭分别浏览。
9. 宏草稿与状态详情在右下区域左右并列，内部另有可拖动分隔线；详情隐藏时草稿占满。详情按字段高亮不同值，模板红、实际绿；宏来源语句、定位按钮及说明在下方单独分区，留出间距。

分析面板和入口各自占用布局空间，避免覆盖技能或原显示工具栏。模式内技能点击不会删除、拖动或修改技能参数；退出后恢复原移动、复制操作。序列/配置变化自动更新并重新定位保留的组合；组合确已消失才提示重选。Escape 取消当前选择和分析请求。显示上的自动盾回不算模拟输入。

## 匹配与证据口径

- 只遍历非 `triggered` 的成功主动释放；包含血怒等非主 GCD 技能。
- 连续性以主动释放序列为准，允许重叠命中。框选不连续的技能会提示重选。
- 同一技能的等级、怒气档位可归为基础名；阵云、月照和雁门保留各自技能名，雾海技能保留完整名。
- 正样本为每处组合对应步骤的释放前状态。负样本明确分为三类：全部匹配范围外的同技能、匹配范围内其它步骤的同技能、其它技能。重叠组合先标记全部正样本，剩余位置再分组，互不重复。显示组合内/外同技能的状态对比与逐次释放详情。
- 状态保留采样时刻和施放时刻。技能内部时间推进、网络延迟等可能使它们不同；没有每帧和等待期间的决策快照。
- 任一步骤的条件成立不保证整个组合会连续执行，也不代表宏的优先级、技能可释放性或最终 DPS 已验证。

| 指标 | 定义 |
| --- | --- |
| 覆盖 | 条件为真的目标位置数 / 全部目标位置数 |
| 组合外同技能误匹配 | 条件为真的、全部匹配范围之外的同技能释放数 |
| 其它位置额外匹配 | 条件为真的、组合内其它步骤同技能或其它技能的释放前位置数 |
| 漏匹配 | 条件为假的目标位置数 |
| 未知 | 相关状态字段缺失，无法求值的位置数 |
| 精确率 | 目标真值数 / 全部已知真值数 |

存在组合外同技能时，先按这组对照能否被完整区分、该组 F1 与未知惩罚排序，再按所有负样本的 F1、未知数量、额外匹配、覆盖数量、条件项数、字符数和表达式稳定排序，避免大量其它技能稀释关键反例。没有组合外同技能样本时明确显示证据不足，并使用全局排序。未知正样本计入未覆盖，未知负样本不被当成假值。相同完整真值表的候选合并；其它写法可展开，这些写法在别的战斗状态下不一定相同。

## 条件与边界

支持 `rage`、`sun`、`energy`、自身和目标 Buff、有无 Buff、自身 Buff 层数、Buff 剩余时间、技能是否冷却、技能充能、上一成功主动技能，以及有限 AND/OR 组合。

- `rage` 为怒气，`sun` 为测试服暴怒，`energy` 为格挡；缺失值不补 0。
- 满层充能和 GCD 使用 Player 的实际 getter；旧的冷却显示文本不参与推测。
- 永久 Buff 为活跃且剩余时间 0；缺失 Buff 的 `bufftime` 判断为假。
- Buff 条件只输出真实宏名称或别名，不输出数字 ID；没有可用名称的内部状态不参与推荐。内部匹配仍按实际 ID，重复 ID 按运行时最后条目求值；保留游戏姿态状态。
- `bufftime` / `tbufftime` 阈值最多一位小数，直接在 0.1 秒网格生成，再用未舍入的原始快照计算分数；不是在输出阶段截断数字。主候选和其它等效写法遵守同一约束。
- `last_skill` 包含非主 GCD 主动技能，并遵守当前执行器的基础名规则。
- 每条候选由现有宏解析器重新解析，并校验渲染前后的语义；不支持的状态不会被当成真。
- 不推断生命、目标数量或奇穴常量；这些字段当前不参与推荐。
- 默认搜索最多两项条件，界面最多返回 120 组候选。API 最多支持三项、1000 组；主动技能上限 2048 次、单个快照每类状态上限 256 条、请求上限 8 MiB。
- 数值按观察到的分界点抽取，必要时按分位裁剪；语法类别轮流分配候选预算，最多 4096 个单条件，组合搜索宽度 40。不宣称穷举无限阈值和任意长度表达式。

## 工程与验证

- `frontend/macro-assist.js` / `.css`：选择结果、状态检查、面板和复制；`app.js` 仅接入既有框选并提供本次模拟返回值。
- `backend/src/macro_assist.rs`：只读 `/api/macro/assist`，严格三值求值、有限搜索和排名，在阻塞任务池计算。
- `EventState`：增量提供实际采样时间和技能状态，不改变战斗生命周期；Lite 不构造这些字段。
- 推荐只复制，不覆盖用户宏或写入用户数据。版本、心法、序列及完整模拟配置变化后，阻止复制旧推荐并自动更新，保留选择；异步旧结果不能覆盖新选择。
- 回归位于 `backend/tests/macro_assist/`；浏览器关键路径脚本为 `tools/macro-assist-ui-smoke.py`，请求写入均拦截，必须使用隔离 localhost 后端。

## 原布局中的宏草稿与对照

- `POST /api/macro/assist/program` 复用现有请求，返回各步分析和最多六个联合方案。每步最多 96 条候选，联合候选池 12、beam 32，探索条件和前后行优先级；不是每步首选的直接拼接。联合匹配、冲突和组合外同技能成立均为模板快照统计，尚未验证可释放性。
- `frontend/macro-editor.js` 保存独立草稿，提供光标插入、选区替换、撤销、载入当前宏、复制及 Ctrl+Enter 运行；按经过核实的用户、版本/心法隔离浏览器草稿。分析刷新不覆盖手工修改，过期结果和宏行定位受版本检查。
- `frontend/macro-draft-panes.js` 将编辑区左右分为盾宏/通用宏和刀宏，完整文本仍是保存、撤销、复制与运行的共同来源。载入按首个有效刀页边界切分，标准盾/刀分页头不显示在输入区，由编辑器保留其语义；复杂分页与原文顺序保留。右栏输入无分页头时自动补刀页；首次创建刀宏时，无显式分页的左栏自动采用盾页，防止通用页遮蔽刀页，并纳入同一步撤销。仅编辑左栏仍支持通用宏，载入已有盾宏也不会丢失盾姿态限制。已有原文中的通用页优先级保留并提示。插入与宏物理行定位映射到可见栏，隐藏的完整文本框不接受焦点。
- 模板请求在发送前冻结到模拟结果；宏运行复制完整环境，仅替换执行策略（宏文本/占位序列/时长，并移除手工按序号配置的引导、偏移、移除 Buff 操作）。实际结果不写入左侧模板、`lastSimResult` 或正式宏。
- `frontend/macro-alignment.js` 对主动技能做顺序对齐，包含非主 GCD，排除派生/虚拟操作；最多 2048 主动事件。数组索引保留各自原 timeline 位置，时间只用于同等技能匹配数量时的消歧。怒气档位、资源、引导跳数和时间偏差单独标注，插删后恢复对齐。
- 右侧通过 `decorateSeqItems(result, {container, readOnly:true})` 和 `_buildSeqItemInner` 复用原序列的图标、名称、角标及 tooltip，不复制另一套渲染。缩放、文字/图标与辅助信息跟随现有设置，新增配色全使用主题变量。
- `frontend/macro-layout.js` 仅保存面板比例与分隔交互；层级切换、拖动和同步滚动不触发模拟。色带只连接同侧、同一显示行内连续的差异技能，正常技能和人工换行会截断。同步滚动按各自可滚动距离的比例进行，不把短序列的滚动上限强制套给长序列；点击差异时以对应技能定位为优先。
- `frontend/macro-state-diff.js` 用 DOM 行对齐模板与实际状态，Buff/CD/充能按身份匹配，单侧记录保留；资源、名称、层数和剩余时间分别比较。时间按显示的一位小数比较，缺记录明确标示，不补零；双方均未提供的可选资源不展示。所有名称使用 `textContent`。
- 当前比较双方的 `[0, 模板 fight_time)` 主动施放，窗口外数量另列；不展示未经严格共同伤害窗口结算的 DPS 百分比。详情展示真实状态与执行宏页/行，不能从释放前快照倒推出判断时刻的根因。
- 局部前缀重放、精确决策 trace 和严格共同窗口伤害统计仍为后续设计，当前按钮仅运行完整草稿。
