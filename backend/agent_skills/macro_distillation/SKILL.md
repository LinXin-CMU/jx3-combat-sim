# 宏蒸馏 · macro-distillation/v2

目标：从当前冻结循环中提取可执行的宏条件，保持用户关心的循环结构和表现。

## 主线

1. `distill_macro` 从完整冻结时间轴调用旧 macro_gen 生成器，然后连续执行工作流 A 的算法调优：释放次数偏差较大时先 cast-diff，再安全剪枝、同页相邻 swap、条件阈值调整。下一轮从上一轮选定宏继续，直到稳定或额度用完。每个候选实际模拟评估，返回调优后的宏、初稿/最终指标、每页字数和规则诊断。规则诊断属于生成初稿，最终行为以调优实测为准。
2. 结合用户目标、当前配装/奇穴/秘籍、循环结构理解每条规则。查看诊断中低匹配或降级为无条件的规则，按需用 `inspect_timeline_events` 查看目标技能释放与未释放位置的状态。攻略用于解释机制与帮助选条件。
3. 根据 `tuning.final` 与 `tuning.target` 的技能次数、DPS 和 `missing_target_skills` 找剩余差异；`tuning.initial` 仅用于看算法改善了多少。把调优后的完整候选放入 `compare_scenarios` 的 `candidates[].patch.macro_text`，取得伤害与时间轴差异。大量技能缺失时，先检查起手资源、当前页和高优先级行是否让后续技能无法执行；条件修复后继续试跑。
4. 在算法候选上根据实际差异微调：条件阈值、技能优先级、分体态页、起手与常规段衔接。结合共享释放状态设计条件，再测试修改后的完整宏。比较 DPS、技能次数、资源/覆盖、等待与关键技能触发，选择实测更符合用户目标的一版。把工具调用留给具体候选的试跑与修订，已有的语法和机制信息直接用于实现。
5. 正常回复只交付最终选定的一份完整宏、每页字数、主要修改依据、实测结果及剩余差异。中间候选、试错过程和逐轮记录留在调试信息。最终 artifacts 只放选定版本；剩余时间不足时选已测版本并明确验证状态。

## 运行语义

每个决策点按当前体态选页，从头扫描，执行第一个满足条件且实际可释放的技能；施放后状态变化，再从头扫描。条件与优先级共同决定顺序。页尾无条件盾回可作为兜底，是否合适取决于前面技能的条件和可释放性。

`#page shield` / `#page blade` 是模拟器的体态分页标记。纯一键描述操作方式，分体态描述执行范围。按当前场景选择结构，用户对操作方式的偏好可以通过 ask_user_question 澄清；武器与奇穴事实从场景读取。

怒气、Buff存在/层数/剩余时间、技能充能等可构成共享释放条件。将实际释放位置与相似状态下其它技能的位置对照，核对误触发和漏发。多次绝刀的顺序可以通过施放后状态变化间接表达，具体可复刻程度由条件区分能力与测试结果判断。

每页宏正文按现有编辑器口径最多 128 字符，计入正文换行；分页标记单独存储。交付前检查每页，超限时精简条件或重新安排页面。`last_skill` 等模拟器扩展条件的游戏兼容性需要另外核对，模拟通过与游戏可用分开说明。

## 自主迭代

模型修改后可再次调用 `distill_macro` 并传入完整 `macro_text`，让算法以该候选为起点调优。默认每次最多 384 次轻量模拟，按实际次数计入本轮模拟预算并预留后续验证空间；达到次数或时间额度时返回已测候选与停止原因，可根据剩余价值决定是否继续。传入上一轮选定的宏可以续调；相同参数调用会复用已有结果。

算法沿用工作流实现：血怒/业火麟光/偃守孤旌次数偏差权重 5；cast-diff 要求加权偏差下降且 DPS 跌幅不超过 0.5%；剪枝允许 0.2% DPS 波动，对该阶段基线已释放的技能限制敏感/普通漂移 1/2 次；swap 接受至少 0.2% DPS 提升；条件调整允许 0.2% DPS 波动。阈值用于算法筛选，模型结合玩法选择最终方案。算法实测说明这份候选跑出了什么；完整复刻程度由原轴与候选的实际差异判断。

上述步骤是工作方法。依据新证据可以回查状态、修正假设或提前交付。模型自行选择实验方向，常规只读对比可以直接执行。完整证据在后端留存；所有候选继承冻结环境，保存或应用宏仍由用户决定。
