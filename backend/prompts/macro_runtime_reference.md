# 本项目宏语言与运行语义

来源：macro_parser.rs、macro_engine.rs、macro_eval.rs。这是模拟器实现说明；游戏客户端的能力判断另以当前版本资料为据。

## 执行方式

宏是按状态反复求值的优先级表。每个决策点按当前体态选页，从页首扫描条件，再按源行顺序选择首个当前可释放的技能。条件成立的技能仍需通过体态、资源、连招、冷却、GCD、引导等检查；前面的技能不可释放时继续检查后面的技能。成功施放后更新状态，下一决策点重新从页首扫描。

重复按键也会重新检查条件。带 `nobuff:名称` 的语句在该Buff已存在时不能进入技能池；是否额外施放或刷新由当时的条件与技能可用性决定。

因此，把血怒排在斩刀下面只表达优先级；斩刀不可释放而血怒条件满足时，血怒仍可能施放。分体态页仅限定在哪个体态参与扫描，具体爆发时点由条件和实际可释放性决定。独立辅助宏键也会在每次按键时重新求值，其按键时机属于输入条件。

`#page shield`、`#page blade`、`#page wall` 为模拟器分页声明，也支持擎盾、擎刀、盾墙。按源顺序选第一个无过滤或匹配当前体态的页；均不匹配时回退第一页。无过滤的一页宏可在各体态参与求值。停手只推进时间，体态变化取决于技能和Buff效果。

`/cast [条件] 技能名`、`/fcast [条件] 技能名`；单条条件也可省略方括号。`/fcast` 可打断引导，仍需满足其它施放条件。空行及 `//` 注释跳过。

## 条件表达

- `&` 表示同时满足，`|` 表示满足其一。两者等优先级、右结合：`A&B|C` 解析为 `A&(B|C)`。条件树没有括号分组语法；展示用全括号语义以解析器投影为准。
- 逗号是名称中的普通字符，不能表达逻辑与。`buff:狂绝, nobuff:血怒·惊涌` 会被当成一个Buff名称；同时检查两个状态写 `buff:狂绝&nobuff:血怒·惊涌`。
- `rage>49`：当前怒气比较；支持 `>`、`<`、`=`、`>=`、`<=`、`~=`。本项目明确实现了怒气条件。
- `buff:名称` / `nobuff:名称`：自身Buff存在/不存在；`buff:名称=2` 比较层数。
- `bufftime:名称<5.3`：已存在Buff的剩余秒数。Buff缺失时该判断为false；缺失情况用 `nobuff` 表达。倒计时越小越晚，实际触发还受其它条件约束。
- `tbuff:` / `tnobuff:` / `tbufftime:` 对应目标Buff。
- `skill_energy:血怒>1` 比较当前可用充能层数；充能与怒气、Buff层数分别读取。
- `skill_notin_cd:名称` 按实现检查技能冷却，充能技能有可用层数时视为独立冷却可用，其余检查见 Player::is_skill_not_in_cd。
- `last_skill=斩刀` / `last_skill~=斩刀` 比较上一次实际成功释放的技能，扫描宏行不更新它；成功施放后按基础技能名更新。支持名称或可解析的技能ID。本项目实现这一条件，游戏端兼容性需对应资料确认。
- `skill:数字` / `noskill:数字` 当前执行器实际按玩家是否拥有该奇穴ID检查；这点以实现为准。
- `life` 与 `nearby_enemy` 在本模拟环境中分别按满血比例1和单目标1求值。

## 从手动轴提炼条件

把目标释放位置作为正例，同时查看相同体态、相似Buff/充能状态下未释放该技能的决策点。候选条件应区分两组状态；只命中所有正例还不足以证明完全复刻。结合相邻动作、Buff剩余时间与层数、充能、资源和可释放性提炼条件，再核对实际施放时间、漏发、额外触发及整体循环变化。

用户补充宏页或输入方式时，更新的是执行环境，原目标和已有候选继续保留。修改候选条件时指出新增证据如何改变判断。涉及普通宏与手动轴的混合执行时，先核对当前工具支持的输入方式；单条辅助宏替换完整循环得到的DPS不代表原轴的辅助效果。
